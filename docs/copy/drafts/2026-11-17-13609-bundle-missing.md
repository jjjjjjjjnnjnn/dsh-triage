One detail that may save you a step: `dependencies` and `dsh.profile.bundles` are **two separate fields**, and only the second one drives composition. So the state you printed —

- `dependencies['dsh-plugin-wsl-env']` → target commit ✓
- `dsh.profile.bundles` → only `@deepseek-ai/dsh-base` and `@deepseek-ai/dsh-web-app` ✗

— is exactly "installed, but never composed". The reported `application: applied` is consistent with that: the install step succeeded, the selection did not survive.

Two `node -e` lines from the profile directory read both fields at once:

```bash
cd <DSH_HOME>/profiles/gate
node -e "const p=require('./package.json');console.log('dep', p.dependencies?.['dsh-plugin-wsl-env']);console.log('bundles', p.dsh?.profile?.bundles)"
```

If `bundles` is missing the name, a restart cannot recover it — the array is the selection, so it has to be written back (re-running `dsh plugin --profile gate add '<the same spec>'` should write both fields; editing the array by hand works too, but back the file up first).

A hypothesis, clearly labelled as one: the update path looks like *uninstall → install with the current selection*, and the selection is probably keyed by the bundle **name** from the install record. A Git spec may not round-trip through that record, so the dependency gets rewritten while the selection is dropped. The registry path keeping the bundle fits that shape. The before/after `package.json` you offered would settle it: if the array still contains the name at the `uninstall` boundary and loses it at `install`, it is the re-add step; if it is already gone before `install`, the removal step is doing it.

For reference, our tool prints this three-way split (on disk / listed in `dsh.profile.bundles` / actually composed) and reads nothing else — but the two lines above already answer the question without installing anything: https://github.com/jjjjjjjjnnjnn/dsh-triage

Boundary: this reads published manifests and local files, not your machine. Declaration-layer admission does not prove runtime health.
