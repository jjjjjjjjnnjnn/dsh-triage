补一个可以自己复算的判据，给「为什么升宿主没用」这件事一个确定的答案。

`^0.1.0-rc.3` 对 `0.2.2-rc.3` 是**不满足**的：caret 在 `0.x` 上只放行 `<0.2.0`。同一套算术下：

| 声明 | 对宿主 `0.2.2-rc.3` |
|---|---|
| `^0.1.0-rc.3` | 不满足 |
| `0.2.1-rc.3`（精确钉定） | 不满足 |
| `^0.2.1-rc.3` | 满足 |

所以宿主从 0.2.1 升到 0.2.2，**不会**放宽插件自己写的那条区间；只要 profile 里还是写着 `^0.1.0-rc.N` 的旧构建，它在声明层就注定被拒，表现出来就是「工具消失、没有报错」。

装之前可以先看它自己怎么声明，再决定装哪个版本：

```bash
npm view @deepseek-ai/dsh-tool-subagent peerDependencies engines --json
```

还有一处容易漏的：`pnpm add` 只写 `dependencies`，**不会**把团队 bundle 写回 `dsh.profile.bundles`。组合是按那个数组逐层取的，所以「依赖对了」不等于「bundle 被组合」。核对两行：

```bash
cd C:\Users\Admin1\.dsh\profiles\desktop
node -e "const p=require('./package.json');console.log('dep', p.dependencies?.['@deepseek-ai/dsh-tool-subagent']);console.log('bundles', p.dsh?.profile?.bundles)"
```

你提的第 1 条建议（启动时校验并说明原因，而不是静默禁用工具）是对的，而且它需要**三样输入**才能给出可信结论：宿主版本、插件声明的区间、实际解析到的那一份副本。缺任何一个都只能报「判不了」，这也正是现在看起来像「静默」的原因——没有那份读数的位置。

边界：以上判的是声明层与磁盘上的文件，不是你那台机器；声明层放行不等于运行期一定无故障。
