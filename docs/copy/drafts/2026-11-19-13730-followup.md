One clarification, because it decides which of the two this thread is about.

`plugin add` is not the exemption path: it re-resolves the profile's dependency graph at the version you name, so the rc.3 transitive peers are replaced rather than permitted. `allow-version` is the exact-version admission the reporter hand-wrote into `compatibility.json` — that is the one that loads an older package without fixing the drift.

So they answer different questions. `allow-version` boots a profile that cannot otherwise start; `add <bundle>@<runtime>` performs the alignment you are asking the updater to do automatically. Neither replaces the updater fix — the invariant you state is the right one — but one is a stopgap and the other is the operation itself.

Whether `add` also evicts a row that a stale copy shadows is the reporter's run to observe; I did not measure that.
