# ADR-0015 · 本地面板的速率上限：要么给一个，要么写清为什么不给

> **Status**: **proposed**（2026-11-03，R75；**未实施，等 HUMAN 签字**）
> **票号**: `T-814`（R49 发现；`docs/SECURITY.md` §4.2 现在只写了单飞）
> **取代**: 无。本 ADR 不改任何判定，只决定「同一秒里被点十次会发生什么」
> **依据代码**: `packages/plugin/src/serve.ts`（`singleFlight` 在 `:429`、`audit` 只在 `--audit` 时挂载在 `:235`）

---

## 1. 背景

`serve` 的扫描有**两个入口**，而它们共用同一个 `context.audit`：

| 入口 | 谁在用 | 现状 |
|---|---|---|
| `/api/summary` | 面板首屏与「刷新」按钮（`serve.ts:1251 refresh()` → `:1001 loadSummary()` → `:1003 fetch('/api/summary')`） | **每点一次刷新就真扫一遍** |
| `/api/audit` | raw JSON 页签（`:1151 loadRaw()`），面板里只读一次 | 每次请求真扫 |

现在只有**单飞**（`singleFlight`，`serve.ts:429`，挂在 `:235`）：并发请求共用一次扫描，但**挡不住顺序请求** —— 每秒点一次刷新，就是每秒一次全量扫描。而且它**故意没有 TTL**（`:425-427` 原话：`Deliberately has no TTL`）。

这不是理论问题：R68 量过面板首屏的真实时延分布（n=21，median 921ms、p90 2439ms、max 5557ms），其中 4 次慢跑都在「同段还在跑另一个 Host + 安装」的机器上。**扫描本身已经是秒级 CPU 活**，叠上顺序请求就是可预期的风扇起飞。

R75 之前 `docs/SECURITY.md` §4.2 只写了「单飞挡住了并发」，**没有**回答顺序请求（R75 已补一句「顺序请求不设上限（现状）」）。`T-814` 要求二选一：给上限，或出一份「本地面板不设限」的 ADR 说明理由。

> **一处必须写死的范围**：这条上限要挂在**共享的扫描层**（`context.audit` / `singleFlight` 那一层），不是挂在某一个路由上 —— 面板的刷新走的是 `/api/summary`，只给 `/api/audit` 加缓存会让验收全绿而问题原样保留（R75 的 reviewer 抓到的正是这个形状）。

## 2. 两个案（都要签字，选一个）

### 案 A（推荐）：1 秒复用窗口 + 响应里说清

- 在**共享扫描层**加一个 **1000ms** 的复用窗口：窗口内的请求直接返回上次结果，响应体加 `reused: true` 与 `age_ms`；`/api/summary` 与 `/api/audit` **同时**受益；
- 窗口外照旧真扫；`--audit` 未开时行为不变（501）；
- 面板的「刷新」按钮**不禁用**，但窗口内点击会看到同一份结论（`reused: true`），不会看到假的新数字。

**理由**：1 秒远小于 DSH 插件变动的真实频率（装/卸插件是分钟级动作），却足以把「狂点刷新」从 N 次扫描压成 1 次；`reused` 字段让「这份答案是什么时候算的」可读，不会把旧结论伪装成新结论（R62 的教训：加载态不能伪装成结论，反过来，缓存也不能伪装成新算）。

**代价**：用户刚 `dsh plugin install` 完立刻点刷新，最多要等 1 秒才能看到新结论。这是本 ADR 唯一的体验代价，必须写进 README 的 `serve` 段落。

### 案 B：不设上限，但把理由写死

- 保持现状（只有单飞）；
- 在 `docs/SECURITY.md` §4.2 写清：**只绑回环、单用户、扫描是只读、`--audit` 默认关**，因此不设速率上限；同时写明「本地面板不防同机同权限进程的拒绝服务」属于 §5 的非保证范围。

**理由**：面板是**人点的**，不是被爬的；加缓存会让「我改了配置为什么没变」变成一个要解释的问题。

**代价**：把「用户自己把自己点卡」当成可接受风险；`T-814` 的原文正是担心这一点。

## 3. 建议

**选 A**，并把窗口做成常量（`AUDIT_REUSE_MS = 1000`）而不是配置项——一个需要调的速率参数，最后一定会有人调到 0。

## 4. 后果（按 A 实施时）

| 方面 | 影响 |
|---|---|
| 行为 | **两个扫描入口**（`/api/summary` 与 `/api/audit`）在 1 秒内返回同一份结论，响应多两个字段（`reused` / `age_ms`）；`audit --json` **不受影响**（缓存只在 HTTP 层） |
| 可测 | 单测：同一路由两次连续请求 → 第二次 `reused: true` 且 `age_ms <= 1000`；等 1.1 秒后 → `reused: false`；并发 5 个 → 仍只扫一次（现有单飞断言不变）；**`/api/summary` 与 `/api/audit` 各一条**，并有一条「两个路由共享同一个窗口」的断言（否则就是本条 ADR 最容易犯的错：只给一个路由加缓存） |
| 对外 | README 的 `serve` 段落加一句「刷新结果最多复用 1 秒」；`docs/SECURITY.md` §4.2 从「单飞」改成「单飞 + 1 秒复用」 |
| 判据 | 一字不动 |
