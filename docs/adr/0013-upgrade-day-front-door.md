# ADR-0013 · 正门 = 升级日（卡片是第一种外壳）

> **Status**: accepted（2026-10-29，R47；HUMAN 在四选一中选 B，记账见 `audit/SIGNOFF.md` R47 行）
> **取代**: 无（这是**定位**决策，不改任何判据；四桶、`improved` 五门槛、`admission.ts` 规则顺序、`data/gold/` 全部原样）
> **依据产物**: `data/results/market-baseline-2026-10-29T12-20-00.000Z.json`

---

## 1. 背景（R46 之前的真实处境）

R46 交接时的状态是：构建侧 430 测试 / 9 门全绿、5 个里程碑交付、10 个真实案例 9 命中——**而 npm 上周下载记录是空的，三条渠道 PR `merged 0`**。

三个产品存在性问题一直没被回答：

1. 为什么大家一定要下载？
2. 为什么要有这个功能？
3. 为什么不用别人的？

R47 用外部数据回答（同一份产物）：

| 问题 | 数据 |
|---|---|
| 有没有人装诊断类？ | 品类合计周下载 **1,988**；市场类 **380,240**、装饰类 **411,844**、能力类 **304,666**、harness 本体 **540,139** |
| 我们呢？ | `dsh-triage` **无下载记录**（downloads API 404 → `no-record`，不写成 0） |
| 痛点真吗？ | 上游最近 **842** 条 Discussions：**414 条（49.2%）** 命中故障聚类，其中 **278 条（67.2%）零回复** |
| 别人做不了吗？ | `dshmarket`（292k 单包周下载）在**安装那一刻**回答「装不装得上」；`dsh.so` 用 L1–L5 干净沙盒实测覆盖约 22,180 条；`dsh-field-notes` 类人工笔记覆盖踩坑 |

结论：**痛点真、需求形态错**。诊断是「保险」——用户不会被一个还没发生的故障驱动去装一个插件；而赢家全都「在界面里、开箱可感、零配置、高频」。

## 2. 决策

**把正门从「通用检查器」换成「升级日」**：每次 DSH 发新 rc，用**本机已装集合**回答「升上去会坏什么、怎么修」，并把这个答案做成一张**可粘贴的卡片**。

由此产生三条结构性后果：

1. **外壳排序变了**：卡片是第一种外壳，CLI / 面板 / 徽章 / 索引源 / Agent 工具都是放大器（`docs/DESIGN-MAP.md` §4）；
2. **判据不动**：四桶引擎（`upgrade --to`）在 R42 就建好了，本决策只是把它的**输出形态**当产品，不改任何判定；
3. **指标换了**：从「周下载 ≥3,000 / 类目第一」改为「**D5**：2 周内 reactions ≥10 · 外部引用 ≥1 · 周下载 ≥20」，不达标执行 D。

## 3. 备选（R47 呈给 HUMAN 的四案）

| 案 | 做法 | 为什么没选 |
|---|---|---|
| **A** 进别人安装路径 | 把判定做成数据包/库交给 `dshmarket` / `catalog` | 需要 BD，且我们还没有**任何**可被消费的数据；顺序反了（先有样本，再谈被消费） |
| **B（选中）** 升级日 | 用已有四桶引擎，绑在有明确时间点的恐惧上 | —— |
| **C** 作者侧 CI | 给 7,557 个 catalog 条目做兼容矩阵 + Action | 成本最高（跑量 + 维护），且「被引用数」这个指标更晚才动 |
| **D** 承认不是产品 | 降级为作品集 + 给上游提 issue/PR | 这是 B 失败后的**出口**，不是现在的选择 |

## 4. 为什么不是「再加一个功能」

因为数据堵住了这条路：整个诊断品类合计 1,988 周下载已经是这个类的**全部**，其中最强的 `dsh-doctor` 只有 1,175。在这个量级上「把功能做得更好」不会改变采纳，只会增加维护面。**换门口**（B）或**换分发**（A/C）是仅有的两条出路，而 B 是唯一不需要别人点头的。

## 5. 可撤销条件（什么时候该回来重开这个 ADR）

1. **D5 达标**（reactions ≥10 / 外部引用 ≥1 / 周下载 ≥20）→ 升级日成立，进入 A/C 支线（`T-803`/`T-804`）；
2. **D5 不达标** → 执行 D，本 ADR 作废，不做「第 N 个功能」的妥协；
3. 上游把「升级影响」做进官方 doctor/market（`docs/ROADMAP.md` §6 风险表现实化）→ 本 ADR 立刻重开：我们转做**数据与归因提供方**（把自己变成别人的信号源），而不是继续卖卡片。

## 6. 代价与已知缺陷

- **覆盖面窄**：四桶判的是声明层，不做运行期实测；卡片只能回答「声明上会坏什么」，不能回答「升级后真的能跑」；
- **`improved` 只有降级几何**（`BS-42`）：措辞被限制在「目标版本会放行它」；
- **依赖版本号**：用户不关心 rc 号，卡片必须替他们说清「你现在是什么、目标是什么」，否则读不懂（这是 `docs/specs/M6-upgrade-day.md` C1 的由来）；
- **不能替用户决定**：卡片只给分区与修复命令，不给「建议升级 / 建议别升」的评分——那是没有证据的判断。
