# ADR 0003 · 门禁零第三方依赖 + 强制负对照

> **状态**：已采纳（2026-10-26） | 影响面：`scripts/gate_*.mjs`、CI

## 背景

门禁最常见的两种失效方式：

1. **跑不起来**：依赖没装 / 配置漂移 / 版本不兼容 → CI 跳过或静默通过；
2. **永远绿**：检查逻辑写错，实际什么都没验证（vacuous green）。

对一个「判断别人插件可不可用」的项目来说，自己的门禁是空心的，产品就没有资格谈可信。

## 决定

1. `scripts/gate_*.mjs` **只用 Node 内置模块**（`fs`/`path`/`child_process`/`crypto`），不引入 yaml/glob/ajv；
   - 需要 YAML 的检查（patch 行 id）用行扫描，而不是 YAML 库；
2. 每道门必须实现 `--mutate`：注入一个已知违规，**该模式必须 exit 1**；
3. CI 跑两遍：正常（必须绿）+ `--mutate`（必须红，否则 job 失败并打印 `::error::`）；
4. 门的登记表放 `audit/gate_ledger.json`，由 `gate_governance` 校验「登记 ↔ 磁盘」一一对应；
5. 判据/阈值改动需要 spec + HUMAN-SIGN（`PROJECT_RULES.md` 铁律 4）。

## 后果

- 6 道门全部 CAUGHT（见本轮记录）；
- 代价：无法复用 yaml 解析，DNS 之类复杂检查要自己写——可接受，门禁本身就是守边界的东西。

## 替代方案（未采纳）

- 用 vitest 当门禁：门禁与单测混淆，且依赖安装失败会连带门禁失效；
- 只跑正常模式：无法证明门禁不是装饰。
