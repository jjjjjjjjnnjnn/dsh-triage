## 1. 现象：107 条问题，答案就取决于「你装了哪些包」

`needs-their-profile` 这一档有 **178** 条。R88 把它按层级拆开之后，它不是一桶东西：

| 层级 | 条数 | 我们现在的通道能不能答 |
|---|---:|---|
| `composition` | 54 | **能** —— 冲突 / 重复副本 / 被 hoist 遮蔽，正是已装集合 |
| `admission` | 33 | **能** —— 「这个构建会不会被拒」是引擎的主体 |
| `upgrade` | 20 | **能** —— 四桶与 `improved` 已经在算 |
| `runtime` | 71 | **不答** —— `ADR-0009` A：运行期读数我们不读 |

也就是 **107 条**落在「读用户已装集合」这个我们本来就在做的事上，**71 条**落在我们**明确决定不做**的层上。
（这条拆分是 R88 才有的：交接文档把这 178 条整体写成「我们的强项」，那对 71 条不成立。）

这 107 条的共同形状是：**提问者没有跑任何东西**。他不知道跑什么、跑完贴什么、贴出来会不会泄露路径。
引擎已经能给出答案，缺的是**把答案交到他手里**的那一步。

样本（编号可在产物里复算）：`#707`（node 版本与 MCP 要求不符）、`#725`（工具调用报 `unknown tool ""`）、
`#1358`（子代理没继承模型配置）、`#3397`（某供应商下缺模型）。

## 2. 现有通道盘点（缺的是形态，不是判断力）

| 已有 | 是什么 | 为什么还不够 |
|---|---|---|
| `dsh-triage status`（无参） | 一屏人话结论 | 面向屏幕，不是面向粘贴；含本机路径 |
| `audit --json` | 全台账 | 太长、含根路径，没人会贴进论坛 |
| `upgrade --card --out` | 卡片写盘 | 只覆盖 upgrade 一层 |
| `summary.ts` | 人话投影（CLI 与面板共用） | 没有「可粘贴」这个输出形态 |
| `redactRoots` | 路径脱敏（已有，e2e 覆盖） | 没有接在一条「贴这个」的命令上 |

所以缺的**不是**新判据、**不是**新证据来源，而是同一份结论的**第四种外壳**（前三种：终端、面板、Agent 工具）。

## 4. 两个版本，分开决定

### 4.1 版本 A：纯文档（交付轮，**D5 判定前可以做**）

一页 `docs/distribution/answer-kit.md`：三条命令（`status` / `audit` / `upgrade --to next --card`）
+ 一段固定的粘贴模板 + 一份「贴之前删掉这些」的清单。

- **为什么现在能做**：不加命令、不改判据、不进 `packages/`，只是把已经存在的东西写成可照做的步骤。
- **验收**：模板里每条命令在本机真跑一次并落产物；模板必须写明**它不证明「装得上」**。
- **负对照**：把模板里的 `~` 展开成绝对路径后仍声称「可以直接贴」→ 判红（人工复核项，这一条**不可**机器化，
  如实写在这里而不是假装有断言）。

### 4.2 版本 B：新命令（交付轮，**D5 判定后**）

`dsh-triage answer --profile <p>`：输出固定块（人话结论 / 计数 / 最多 3 条要看的地方 / 复算命令）。

三条**能真红**的验收：

| 编号 | 验收 | 负对照（必须真的红） |
|---|---|---|
| **X1-N1** | 输出里不出现绝对路径与家目录（复用 `redactRoots`） | 把 `redactRoots` 换成恒等函数 → 构造一个含 `/home/alice` 的 profile，断言红 |
| **X1-N2** | 同一 profile 两次运行逐字节相同 | 往块里塞 `Date.now()` → 断言红 |
| **X1-N3** | 块里的每个计数与 `audit --json` 的同名字段**逐项相同** | 块里改一个计数 → 断言红（禁止第二套算法） |

## 5. 与 D5 冻结的关系

- 版本 A **不改变 D5 的三个数**，也**不算**需求证据——它只让已有结论更容易被看见。
- 版本 B 是**新功能**。按 R86 的决定（`docs/HANDOFF.md` §3、`T-855`–`T-858` 同样处理）**推迟到
  `2026-11-15T20:24:37Z` 之后**，由 `judgeD5` 的结果决定它在 D 线的哪一格：
  - `fail` → 它属于 D-2 / D-3 的「让已有结论可被看见」，**不是**新判据，符合 `docs/11-d-path.md` §2；
  - `pass` → 它可以作为增长动作之一，但仍要 HUMAN 点头；
  - 判定前 → **只写这份 spec，不实现**。

## 6. 明确不做

1. **不自动回帖**：块由人贴，工具不碰外部账号。
2. **不做运行期诊断**：那 71 条 runtime 问题不是「缺证据」，是我们决定不读（`ADR-0009` A）。
3. **不做「一键复制我的机器」**：块里可以有 profile 名与计数，**不含**包内容、不含凭据、不含绝对路径。
4. **不承诺「贴了就能解决」**：答案是行级归因，不是修复。
