## 1. 现象：160 次探针，160 次同一个原因

`probe-unreadable` 有 **90** 条线程，背后 **160** 次探针，**全部**记的是同一句话：

```
npm has no package <name>
```

没有一次是网络失败、没有一次是 401/私有 registry、没有一次是限流。名字长什么样是这个样子的：

| 名字形状 | 次数 | 例子 | 它其实是什么 |
|---|---:|---|---|
| `upstream-module-or-absent` | 131 | `@deepseek-ai/dsh-browser`、`dsh-fs-local`、`DSH-internal` | 上游**模块名**，不是 npm 包 |
| `version-suffixed` | 19 | `dsh-v0.1.2-alpha.3`、`DSH-0.2.1-rc.3` | 版本号粘在名字上 |
| `file-name` | 6 | `DSH-crash-report-2026-10-24.zip`、`dsh-YYYY-MM-DD.error.log` | 附件名 |
| `version-or-path-fragment` | 4 | `@4.22.4/node_modules`、`@0.34.5/libvips` | 路径片段 |

## 2. 为什么这条必须写下来：它是我们自己测量里的假信号

交接文档的假设是「声明层读不到（私有 registry / 404 / 已被弃用）」。证据说不是：

- **补 registry 兜底没用**——一个不存在的名字，重试一百次也还是不存在；
- **走 probe 隔离实测没用**——隔离沙盒也装不上一个不存在的包；
- 真正的缺口是**抽取精度**：我们把上游模块名、版本号、附件名当成了包名去问 registry。

后果有两层：

1. **覆盖率口径**：README 的「可判口径 74/505」把这一档**从分母里摘掉**，理由是「读不到」。
   如果这 90 条其实是「名字读错了」，那句摘掉的解释就是错的（数字不动，**理由**要改）。
2. **工程判断**：按原假设去做 registry 兜底，会写出一个**永远不会命中**的分支——
   这正是本项目最忌讳的「看起来专业的猜测」。

## 4. 若做属于哪一型 + 最小可证伪验收

### 4.1 交付轮（可先做，不动任何数字）

在抽取之后加一层**名字合法性过滤**：不合法的一次探针都不发，并且在产物里记成
`name-not-a-package`（新字段），**不动** `tier` 名、**不动**任何计数。

验收（三条都能真红）：

| 编号 | 验收 | 负对照 |
|---|---|---|
| **X2-N1** | 一份 **20 条**的夹具（路径片段 / 版本后缀 / 附件名 / 真·缺包 各 5 条）：前 3 类**一次探针都不发**，第 4 类照常发 | 把过滤器改成恒真 → 前 3 类发出探针 → 断言红 |
| **X2-N2** | 产物里新增 `names_rejected[]`，每条带形状与原始字符串；同一输入两次运行逐字节相同 | 往里塞时间戳 / 随机 id → 断言红 |
| **X2-N3** | **计数守恒**：过滤前后 `tiers` 七个数字**完全相同**（只多一个新字段） | 把一条 `not-relevant` 改判成 `probe-unreadable` → 断言红 |

### 4.2 判据轮（若将来要改口径）

若要把档名从 `probe-unreadable` 改成 `no-signal` / `name-not-a-package`，或把它从「可判口径」的分母里
移除/保留，那是**改一个已发布数字的解释**——必须 spec + HUMAN-SIGN，且要在 `docs/specs/question-coverage.md`
里先改口径再改代码。

## 5. 与 D5 冻结的关系

- **不影响 D5 的三个阈值**，也不影响 `judgeD5` 的任何一步。
- 但只要我们**再次对外引用覆盖率**，必须先做完 4.1，或者在那句话旁边写明
  「这 90 条里 160/160 都是『npm 上没有这个名字』」。
- 判定后：`fail` → 属 D-3 维护模式（测量质量），可以做；`pass` → 同样先做它，再谈新功能。

## 6. 明确不做

1. **不追「把上游模块名映射成 npm 包」**：那需要上游的真相，我们没有，猜出来的映射比没有更糟。
2. **不改七档的名字**（那是判据，要走 4.2）。
3. **不为了让数字好看而重分类 950 条 `not-relevant`**（见 X3）。
