# 回帖用的命令包（answer kit）

> **Stand**: R88 (2026-11-05)｜**版本 A（纯文档，0 代码）**｜对应 `T-863` / `docs/specs/X1-reply-command-pack.md` §4.1
> **用途**：有人在论坛 / issue 里说「装了某个包之后 X 不见了 / 升级之后就坏了」，你可以让他在**自己机器上**
> 跑这几条只读命令，把输出贴回来。答案来自他的环境，不来自我们的猜测。
> **取证**：`data/results/answer-kit-2026-11-05T18-15-00.000Z.json`
> （sha256 `807b0851752b1317db552634b6356750ccee4c40b60e0b5b97126959ac05fcf3`）——
> 五条命令在真机上各跑一次，记录退出码、行数、字节数，以及「输出里有没有绝对路径」。
>
> **它不证明什么（重要）**：这些命令输出的是**声明层**读数——「谁的区间不含哪个版本」。它**不证明**
> 升级上去能跑、也不证明某个插件安全。要说「能跑」，只有隔离实测（`probe --execute`）能答。
> 这一句在每条命令自己的输出里也会出现一次，别删。

## 1. 五条命令（复制给他的原文）

### ① 确认装了

```powershell
npx dsh-triage --help
```

**37 行 / 3.3 KB**（本机实测）。看到用法表就说明装上了。

### ② 我这套现在什么状态

```powershell
npx dsh-triage status
```

一屏：读到几项配置、几项已分析、几项「没声明区间」，以及最多两条「要看的地方」。
**12 行 / 0.9 KB**。

### ③ 这一条到底为什么被挡

```powershell
npx dsh-triage why
```

逐行列出结论、原因、修复与证据来源。**16 行 / 1.5 KB**。

> **退出码**（实测 + 源码）：这些命令正常都是 **exit 0**。只有 `why --strict` / `check --strict` 会在
> 「有条目的结论不是 `go`」时 exit 1——那是给 CI 用的，不是崩溃。回帖里看到 exit 0 就够了。

### ④ 完整台账（一般不用贴）

```powershell
npx dsh-triage audit
```

和 ② 同一份摘要，末尾多一句「用 `--all` 看完整台账」。**13 行 / 1.0 KB**。
`--all` 是 170 行左右，`--json` 是 **99 KB**——都别往帖子里贴。

### ⑤ 升级上去会坏什么（只在他问「升级」时用）

```powershell
npx dsh-triage upgrade --to next --card
```

一张 Markdown 卡片：首行是四桶计数，然后逐条列出「会被拒的单元 + 原因 + 修复」。
**60 行 / 4.5 KB**。想精确指定目标就给确切版本号（`--to 0.2.2-rc.1`），那是**全程离线**的。

### 变体：他已经点名了某个包

```powershell
npx dsh-triage check <包名>@<版本>
```

**问题里点了版本就按那个版本判**，不要用 `latest`——`latest` 与作者手上的版本经常不是同一个，
`#10849` / `#8202` 那一类误判都是这么来的。（`check` 会读 registry，`why` 不会；两者共用同一套判定链。）

## 2. 贴什么、贴到哪

**只贴这几样**（按顺序）：

````markdown
环境：<系统> · dsh <版本> · profile <名字>
（粘贴 `dsh-triage status` 的「诊断结论」之后那三行）

我遇到的现象：<一句话>
实际报错：<报错原文，删掉自己的路径>

我跑出来的相关结论：
（粘贴 `dsh-triage why` 的对应那几行，或 `upgrade --card` 的前 10 行）
````

## 3. 贴之前删掉这些

| 要删的 | 为什么 |
|---|---|
| 报错原文里的**绝对路径**（`C:\Users\<你>\…`、`/home/<你>/…`） | 会暴露用户名与目录结构。工具自己的输出**已经**写成 `~\profiles\<名字>` 或只印 profile 名，但**你手抄的报错不会** |
| **profile 名**（如 `web`） | 不是秘密，但没必要；改成 `<profile>` 更好 |
| 任何 **token / API key**（有的报错会带 Authorization 头） | 一条都不要贴 |

**已核对的事实**（`answer-kit-2026-11-05T18-15-00.000Z.json`）：五条命令的输出里
**没有任何绝对路径**——没有盘符、没有 `/home/<user>`。`audit --json` 里唯一与家目录有关的是
`~\profiles\<名字>`（相对路径，指向 profile 而不指向家目录）。

这条承诺有它自己的检查器：`scripts/lib/redaction-check.mjs`（三道正例 + 三道反例的单测），
外加 `--self-test` 会**故意注入**一条带路径的输出，确认检查器真的会红：

```powershell
node scripts/record_answer_kit.mjs --stamp <ISO> --self-test
# 期望最后一行：NEGATIVE CONTROL PASSED · the leak was caught
```

## 4. 你可以替他把结论说出来

拿到他的 `status` / `why` 之后，我们能说的三类话（也是回帖的骨架）：

1. **「这一行被拒了，因为某条 peer 区间不含你正在跑的运行时」** —— 点名哪一条、哪个区间；
2. **「这两项什么都没声明，所以谁也不能说它兼容」** —— 沉默不等于通过，这是本工具存在的主要理由之一；
3. **「升级到 X 会摘掉这些单元」** —— 给四桶计数与逐条原因，并**同时**给边界句「这只比对声明区间」。

不能说的一律不说：不写「安全」、不写「100% 兼容」、不写「升级就好了」——最后一句只有隔离实测能撑住。

## 5. 复算

```powershell
node scripts/record_answer_kit.mjs --stamp <ISO>
node scripts/record_answer_kit.mjs --stamp <ISO> --self-test      # 负对照：注入路径，必须被抓住
node scripts/record_answer_kit.mjs --stamp <ISO> --to 0.2.2-rc.1  # 精确版本 = 全程离线
```

## 6. 边界

- 这些命令读的是**跑它们的那台机器**；同一段解读搬到别人机器上就不成立。
- 行数/字节是**本机实测**，插件多的人会更长（`upgrade --card` 已顶着 60 行的预算）；超出时贴「首行结论 +
  你真的在意的那几条」。
- ①②③④ 离线可用，只有 ⑤ 的 `--to next` 需要读 registry（给确切版本号则不需要）。
- 版本 B（`dsh-triage answer` 一条命令出这段文本）**推迟到 D5 判定之后**，见 `X1` §4.2。
