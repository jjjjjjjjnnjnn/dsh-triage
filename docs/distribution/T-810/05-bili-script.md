# 草稿 05 · B 站脚本（60–90 秒，中文旁白）

> 需要的最小素材：① 终端里「升到 rc.5 → 一张四桶表」的录屏；② `audit` 一屏结论的录屏。两条都能在本机真跑。
> 旁白全部可以直接念；`【画面】` 是要录的东西，`【字幕】` 是要打的字。

---

**【画面】** 终端，一行命令，卡片滚出来。
**【字幕】** rc 升一格，你的「已装集合」掉什么？

旁白：上游 `0.2.1-rc.5` 刚发。我不问「它好不好用」，我问一个更具体的问题——**我这套已经装好的东西，升上去会掉什么**。

**【画面】** 四桶表停在屏幕上（119 / 73 / 0 / 0）。
**【字幕】** 192 个单元里，119 会被拒

旁白：192 个单元，119 个会被拒，73 个判不了。原因几乎全是同一条：声明把 peer 钉死在上一个 rc，目标版本一换，
全部落在区间外。

**【画面】** 展开其中一行原因（`peer …@0.2.1-rc.4 不含 0.2.1-rc.5`）。
**【字幕】** 声明层的判断，不是运行期实测

旁白：注意这句话的边界——这是**声明层**的判断，不是「升级会坏」。它也不会反过来吹自己：真能让它变好的一个都没有，
所以卡片只敢说「目标版本会放行它」。

**【画面】** `dsh-triage audit` 一屏结论。
**【字幕】** 你那一套，得你自己查

旁白：我这台的数字长这样，你的机器上应该不一样——不一样才对。命令在简介里，`--to` 给精确版本时全程离线。

**【画面】** 仓库地址 + 一行「MIT / 只读 / 没证据就说 unknown」。
**【字幕】** 不是你的机器；没证据就说 unknown

旁白：一个很小的开源工具，只做判断，不做市场、不做启动器。
