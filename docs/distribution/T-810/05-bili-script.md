# 草稿 05 · B 站视频脚本（60–90 秒，口播向）

> **录制准备**：
> 1. 终端真实录屏：执行 `dsh-triage upgrade --to 0.2.1-rc.5 --card` 刷出四桶卡片；
> 2. 界面真实录屏：DSH 设置页中“分诊台”面板展示与 `dsh-triage audit` 运行；
> 3. 视频简介需附带开源仓库链接与复算命令。

---

**【0:00 - 0:06 黄金痛点 Hook】**
- **画面**：终端敲下升级指令，DSH 启动后，之前安装好的插件功能或 MCP 工具在界面中消失。
- **字幕**：升级 DSH 之后，插件为什么突然全消失了？
- **口播**：“你有没有遇到过这种情况：DSH 刚升了个新版本，插件明明在目录里，界面上的功能却突然全没了，而且翻遍屏幕连个报错弹窗都找不到！”

**【0:06 - 0:22 机制原理揭秘】**
- **画面**：调出终端日志，高亮那一行准入拒绝（`engines.dsh >=9.0.0 does not include 0.2.1-rc.4` 这类原因），再特写 `package.json` 中的精确 peer 依赖版本。
- **字幕**：不是代码写崩了，而是被启动准入（Admission）直接踢掉
- **口播**：“其实你的代码根本没写错！这是因为 DSH 在启动时有一套准入机制。很多插件为了稳妥，把依赖版本精确写死了上一个 rc 版本。宿主一升级，区间对不上，系统在加载前就会直接把这一行悄悄踢掉。我们在 0.2.1-rc.5 上实测了 192 个插件单元，足足有 119 个当场中招！”

**【0:22 - 0:45 一秒预检与工具演示】**
- **画面**：终端输入 `dsh-triage upgrade --to 0.2.1-rc.5 --card`，回车，四桶兼容报告瞬间滚动出来，高亮显示被拦截的插件和建议命令。随后展示设置页里的集成面板。
- **字幕**：升级前 1 秒预检：谁会被拒、怎么修复
- **口播**：“想在升级前就知道自己装的这一整套插件会不会中招？其实用这个轻量开源工具跑一行命令就行。它直接在本地读取你当前的实际插件组合，一秒生成兼容预检报告，清清楚楚告诉你哪些会被准入拦截、具体原因是什么、该怎么修复，甚至还能直接嵌进 DSH 的设置页里！”

**【0:45 - 0:60 排查与收尾】**
- **画面**：终端输入 `dsh-triage audit` 快速扫出当前状态，画面切换至 GitHub 开源主页。
- **字幕**：纯本地运行 · 零遥测 · 完全开源
- **口播**：“要是你的插件已经不见了，跑一行 `dsh-triage audit` 就能秒级定位原因。纯本地离线运行，不碰你的配置文件。工具已经完全开源，命令和测试卡片数据都在简介里，升级前赶紧给自己这套插件体检一下吧！”
