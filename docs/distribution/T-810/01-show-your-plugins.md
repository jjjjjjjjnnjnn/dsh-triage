## 它能帮你做什么？

如果你在用 DSH 时遇到过以下情况：
- **升级新版本后**，原本好好的插件突然消失了，界面没有报错，但功能全用不了；
- **装了新插件后**，在列表里死活找不到，不知道是哪一步没加载；
- **计划升级最新 rc**，当前已安装了多个插件，不确定升级后是否存在兼容性中断。

`dsh-triage`（分诊台）就是专门解决这类本地插件兼容问题的轻量工具。它直接读取**你本机当前的实际已装插件组合**，提供两项核心能力：
1. **升级前预检**：一键推演目标版本，秒级列出哪些插件会失效、哪些能放行，并输出修复建议；
2. **故障归因排查**：深入分析每一行插件的准入声明与加载阶段，快速查明插件“静默消失”的具体根因（如 peerDependencies 精确锁死旧版本、Entry ID 命名冲突等）。

## 快速上手

### 1. 命令行直接用（推荐，无需常驻后台）

```console
# 全局安装 CLI
$ npm i -g dsh-triage

# 升级预检：升级到下一个版本，当前插件组合会有哪些被阻断？
$ dsh-triage upgrade --to next --card

# 一键体检：我当前的插件有没有已经失效或被拦截的？
$ dsh-triage status

# 深度台账：查看逐行准入判定与生命周期状态
$ dsh-triage audit
```

### 2. 装进 DSH（设置页集成可视化面板）

```console
$ dsh plugin --profile web add dsh-triage
```
安装后，在“设置页 → 兼容性分析”即可直接查看图形化排查界面。

## 核心设计与边界

- **纯本地、零遥测**：纯只读分析，不修改任何 profile 配置，不写入 `~/.dsh`，除解析 `next`/`latest` 标签外全程离线，绝不上报任何数据；
- **声明层静态预检**：主要基于 `package.json` 中的 `engines.dsh` 与 `peerDependencies` 进行准入推演，属于静态预检，不代表动态运行期 100% 无错；
- **集成方式多样**：支持作为独立 CLI 使用、集成进 DSH 设置页，或者作为 Agent 工具（`compat_verdict`）让 AI 助手在装插件前主动自检；
- **数据完全可复算**：
  - 升级卡片判定依据：`data/results/upgrade-card-2026-10-31T09-00-00.000Z.json`（可由命令 `node scripts/record_upgrade_card.mjs --stamp <ISO> --to 0.2.1-rc.5` 复算）；
  - 图 1 混合排查真机记录：`data/results/client-serve-2026-11-01T21-30-00.000Z.json`；
