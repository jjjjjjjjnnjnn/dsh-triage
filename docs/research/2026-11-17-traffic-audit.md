> **一句话**：产品侧已经不是瓶颈，**到达**是。14 天里只有 **19 个唯一访客**打开了仓库；同一窗口有 **1,416 次 clone**（327 个唯一）—— 那是 CI、镜像和扫描器，不是人。唯一的真实第三方互动是 issue #1：一个已经装了 0.3.4 的用户，碰到了一个真 bug，我们修了，他没有留下 star。
>
> **数据**：`data/results/traffic-2026-11-17T13-04-28-424Z.json`（`scripts/record_traffic.mjs`，可重跑）。GitHub traffic 只有 14 天窗口，所以这份快照是「不写下来就消失」的那一类。
> **口径**：GitHub 的 `uniques` 是 IP，不是人；npm 的下载是包，不是人；clone 不是读者。**这份文件里没有任何一个数字可以被读成「有 N 个用户」。**

## 3. 诊断：瓶颈在「到达」，不在「文案」

R114 把首屏改成了「装得上 ≠ 跑得对」，R115 把它送到了 npm 页面。**这两步解决的是「来了之后读什么」，没有解决「谁会来」。**

四个证据：

1. **19 个唯一访客 / 14 天**：这个量级下，首屏好坏、参数表多少行、徽章颜色都不是变量。
2. **1,416 次 clone 对 47 次浏览**：clone 的主语是流水线。把它读成「有人关注」会把整份分析带偏。
3. **唯一的真实互动来自「已经装了的人」**：issue #1 的作者装了 0.3.4，遇到 `dsh-base` / `dsh-web-app` 被误报「not installed」，贴出了 `dist/load.js` 的 `roots` 那两行。**这证明产品在真实故障上是有用的**——但它没有带来 star、没有带来引用、也没有带来第二个人。
4. **可见面还缺三块**：没有 GitHub Release（只有 `v0.1.0-skeleton` 一个 tag）；仓库 `homepage` 是 `null`；`dsh-pluginmarket/metadata`（82 条）里没有我们。

> **一句话诊断**：现在不是「说服读者」的阶段，是「让读者出现」的阶段。所有动作都应该问一句：**它会不会让一个正在排查 DSH 插件故障的人，第一次看到这个仓库？**

## 6. 不做什么（硬边界）

- **不买 star / 不刷下载 / 不自己引用自己**：D5 的判据会排除，且那是伪造证据（`PROJECT_RULES.md` 严禁行为 3）。
- **不在 `#140` 再发第二条催促**：它零 review 是对方的选择；重复 ping 会把「等」变成「骚扰」。
- **不把 1,416 次 clone 说成关注**：那是流水线。
- **不为「扩大知名度」加功能**：D 线只允许安全修复 / 上游适配 / CI / 回归 smoke。曝光要靠分发，不靠第 N 个功能。
- **不重复发同一篇 X / Reddit 内容**：首帖已经发过；重发不是新触达。

## 7. 这份分析自己的边界

1. GitHub traffic 只有 **14 天**，而且只有仓库所有者能读；`uniques` 是 IP，不是人。
2. clone 与下载都无法区分人与机器；本文只使用它们的**形状**（发布日高、间隔日低、clone 远大于浏览），不使用它们的绝对值当人数。
3. `awesome-dsh-plugin` 与 `dsh.so` 的数字是**它们的读数**，按它们自己的刷新节奏变化；本文件记录的是 2026-11-17 的快照。
4. 没有搜索关键词数据（GitHub 不提供）、没有 npm 页面到仓库的转化率、没有 X / Reddit 的展示数。这些是下一层要补的读数，不是本文件的结论。
