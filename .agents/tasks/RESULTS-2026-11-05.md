### 失败的真实形状（attempt 1 日志，`gh run view --attempt 1 --log`）

```
expectation not met: expected blank, got inconclusive
served blank · judged inconclusive (no DOM observation) · 18336ms
```

- 失败步是 `a 200 response with an empty mount point must be caught`（`--mode blank --expect blank`）。
- `no DOM observation` = `judgeRender(null)`：`renderUrl` 在 15s 预算内**一次 DOM 查询都没答**。
- 18.3s ≈ 15s 轮询预算 + 启动/清理开销，指向「循环跑满、始终没读到 DOM」这一分支。
- **但真正的 `render.detail`（`浏览器没开调试端口` / `没暴露页面目标` / 抛错 / 查询超时）被控制台吞掉了**：
  它只打印了 `judgeRender` 的句子，而那句话是信号的函数——没有信号就恒为 `no DOM observation`。
- attempt 2（重跑）上传的三份 JSON 全部 `expectation_met: true`（blank 6946ms / rendered 1024ms / error 6175ms）——
  **重跑覆盖了 attempt 1 的产物**，所以那次红只剩一行日志可查。
- 结论：**不可复现的 flake，成因仍未归因**（与 `BS-60` 一致）。在拿到 `render.detail` 之前，不许猜「runner 慢」或「Chrome 变了」。

### 本轮做了什么（`T-860` 的诊断半边）

| 改动 | 为什么是这一处 |

| `scripts/record_render_fixture.mjs`：失败时打印 `render said: <state> — <detail> · <ms>` 与 signals | 下一次红时**日志本身**就能区分「没开端口 / 没页面目标 / 查询超时 / 抛错」 |
