# adversarial_review（对抗性证伪，强制）

> 触发：任何**门禁 / 判据 / 结论 / 指标**的新增或修改，以及任何把数字写进 SSOT 的轮次。
> 角色卡：`.agents/roles/adversary.md`｜盲区台账：`audit/blind_spots.json`

---

## 1. 唯一 KPI

**能不能骗过这个门 / 这个结论。**

不是「实现是否符合 spec」（那是 SSOT 轴），也不是「代码风格」（那是 reviewer）。只问一件事：**有没有一种输入，看起来合理，却能让门 PASS 而结论是错的？**

## 2. 必交三件（缺一即 NEEDS WORK）

1. **反例构造**：命令 + 输入 + 预期输出，或明确写「未找到反例」并列出已尝试角度；
2. **盲区声明**：这个门/结论**看不见什么**，写进 `audit/blind_spots.json`（含 mitigation + owner）；
3. **死指标核查**：新增的量是否真的进入 `conclusion` / SSOT。算了不判 = 缺陷。

## 3. 四个反假设（本项目专属，必答）

| 反假设 | 问题 | 已知实例 |
|---|---|---|
| 测量伪影 | 是我们的解析/规则错，还是插件真坏？ | entry id 覆写被当撞车 → 标准 profile 27 条假阳性（ADR 0002） |
| 语义漂移 | 上游改了语义，我们还在按旧规则判？ | `engines.dsh` 优先级、prerelease 匹配口径随 rc 变化 |
| 环境错配 | 把 registry 的干净沙盒结论当成「用户本机能跑」？ | dsh.so L4/L5 只能是 `measured-registry`（BS-06） |
| 幸存者偏差 | 样本只来自我们见过的插件？ | 195 抽样里 29.2% 无声明，不能外推成「全生态」 |

## 4. 固定 9 角度（缺一即 NEEDS WORK）

输入缩放 / 单位换算 / 轴交换 / 退化输入 / 顺序置换 / 阈值边界 / 分母膨胀 / 抽样偏差 / 标签互换。

每角度必须写：**命令 + 输出**。不得只写「已尝试」。

## 5. 配额与升级

- 同一门连续 **2 个里程碑**「未找到反例」→ 升级 HUMAN 裁决（禁无限「未找到」）；
- 反例一旦成立，**必须修**，不得以多数票否决；
- 修复后必须回到原角度重跑，并在 SSOT 中留新证据。

## 6. 反模式（禁止）

- 只复述 spec 与实现是否一致；
- 用「看起来合理」代替反例；
- 把负对照没跑过写成「应该没问题」；
- 把「我不知道」写成「无风险」。
