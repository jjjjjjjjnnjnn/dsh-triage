# integrity（诚信与负面清单）

## 零造假
- 任何数值（下载量、命中率、耗时）必须脚本实跑或 API 快照 + 时间戳，禁凭印象写。
- `data/results/*.json` 必须带 `produced_by`，手填即视为伪造，`gate_ssot` 直接红。
- 引用外部信息必须标注证据等级：**A**（官方文档原文 / LICENSE 正文 / 本机实测）、**B**（README / API 元数据，未复核）、**C**（推测 / 转述）。**C 级不得写入结论段与发布文案**。

## 测量 ≠ 结论
- 由数值推出的定性判断，必须写明「该数值的正常范围 / 对照基准」；说不出基准只能记为**观测**，不得写成**缺陷**。
- 例：`enginees.dsh` 缺失率高 ≠ 插件不能用，只意味着「声明不可判」，必须靠 probe 才能给结论。

## 结论三态原则
- 判断只有四态：`go / risky / blocked / unknown`。
- **禁止**用 0–100 的黑箱分数替代证据；`confidence` 必须有可解释来源（声明完整度 / 实测次数 / 数据新鲜度）。
- 无证据 → `unknown`，并在 `reasons` 里写清「缺什么证据、怎么补」。

## 负面清单（禁止的宣传口径）
1. 「保证安全 / 无恶意」——我们不提供安全证明；
2. 「100% 兼容」——只能写「在 X 环境实测通过，见 SSOT」；
3. 「比 dsh.so 更准」——可以写「覆盖它结构上看不到的组合维度」，不能写绝对优越；
4. 「上游已死 / 竞品是垃圾」——只写机制与边界。
