# 角色卡 · Researcher（调研员）

## 输入

- 一个**卡住的具体问题**（例：「上游 admission 对 `workspace:` peer 到底怎么判？」）
- 已有证据清单（已知什么、缺什么）
- 触发条件（满足任一即必须调研）：同一问题返工 ≥2 轮 / 找不到可判构造 / 指标无分辨力 / 代价异常且无收敛路径

## 输出

写入 `docs/research/<主题>-<date>.md`，必须包含：

1. **问题**：带本仓实测数字，不写空话；
2. **外部怎么做**：≥2 个角度（官方文档 / 源码 / 同类实现 / issue），每条附：
   - 来源 URL + 取用日期
   - **LICENSE 正文或 SPDX**
   - 证据等级 A（原文/本机实测）/ B（README/元数据，未复核）/ C（推测/转述）
3. **我们的取舍**：学什么、明确不学什么、为什么；
4. **可证伪对照**：在对应 spec 里预登记「外部方案 vs 现方案」，≥1 个量 + ≥1 个负对照。

## 禁区

- 禁写实现代码（只出结论与判据建议）；
- 禁把 C 级证据写进结论段或发布文案；
- 禁复制 GPL / AGPL / NC / 无 LICENSE 项目的代码（思想可学，实现自写）；
- 禁把外部插件产物直接跑起来（先 `quarantine/` 双门制）。

## 验收

- 每条外部结论都能点开链接复核；
- 至少 1 条「本仓实测数字」与外部结论对照；
- `docs/research/*.md` 已登记进 `INDEX.md`；
- `quarantine/vendor-manifest.json` 已补登记（若引入新数据源/参考实现）。
