## 2. 关键取证（不是「应该能行」）

1. **注册表接受纯对象**：实读 `@deepseek-ai/dsh-tools/lib/index.js#register` —— 只校验
   `output.render` 是函数、`output.schema` 属于受支持 JSON Schema 子集、`timeoutMs` 为正、
   名字不是保留的 `run_code`。**没有 marker**；`defineTool` 只是编译 DSL + 参数校验。
   结论：本包不必引入任何上游依赖（与 `ADR-0010` 对手写 `client.js` 的取舍一致）。
2. **模型可见面**：`schemas()` = `{name, description, parameters, deferLoading?}`。
   真机读到 `compat_verdict`（506 字符描述、参数 `[package]`、该 profile 共 2 个可见工具）。
3. **调用真的走管道**：三次调用都是 `via: registry`（`tools.execute()`），不是直接调定义。
4. **负对照**：未注册的名字在 `tools.get()` 里查不到 —— 所以「可见」不是恒真读数。

- **合规/许可**：只读公开 registry 元数据；读上游 MIT 包的**行为**取证，不 vendor、不复制源码；
  未新增依赖。
- **SSOT 一致**：产物 `verdict` 与 `verdicts[]` 被 `gate_verdict_contract` 直接校验（三种形状
  同时覆盖 remediation 与 missingEvidence 断言）；`step-review` 183 步 / 167 产物全部被引用。

## 4. 对抗性（本轮真跑的四个反例）

1. **「注册了」≠「模型能调」**：所以读 `schemas()` 并真的调用；并记录 `via`。
2. **「工具说 unknown」可能是工具坏**：单测逐个钉住 `{}` / 数字 / `null` / 字符串 / 空白参数
   → `unknown` + `empty-spec`，且 profile 读不出来时不得报成候选问题（`profile-unreadable`）。
3. **跨 profile 取期望**：真踩（见 §5）。现在的期望写在脚本里、并落进产物
   `sandbox.calls[].expected`，声明一改就红。
4. **注入形态**：加 `tools` 到静态 `inject` 会让没有 web 面的 profile 连工具一起不挂载 ——
   改成两半各自 `ctx.inject`，并重跑 R33 的八步回归证明路由没坏。

## 6. 未做 / 边界（不许说过头）

- **没有**证明模型会主动选这个工具；**没有**在 `ptc` 折叠模式（模型直调只允许 `run_code`）下真跑
  过回退分支（`BS-39`）；**没有**跨 profile / 跨机器 / 跨运行时。
- 工具回答的是**它服务的那个 profile** 的运行时；拿另一个 home 的 `check` 结果做对照不是矛盾。
- `go` 只表示「声明层接受这个运行时」，不是「插件能跑」，也不是任何安全结论。
- **一条旧缺口，本轮才点名**：`audit/` 里 **R32–R35 没有 per-round 报告**（那四轮只有机器台账
  `step_reviews.json`）。本文件不补写历史报告——补写就成了事后叙述；INDEX 已按事实改写。
