# AUDIT · R52（2026-10-31）· 采证轮 + 交付轮

> **一句话**：这一轮没有改任何判据，只改了一件事——**「634 次周下载」不再能被当成需求**，并把升级日样本换成真实存在的目标。
> 冻结项（四桶 / `improved` 五门槛 / `admission.ts` / `data/gold/` / 20s / settle / readiness / 9 门）一字未动。

## 1. 为什么开这一轮

接手时核到两件事，都与「D5 能不能被诚实判定」直接相关：

| 事实 | 证据 |
|---|---|
| npm 上 `dsh-triage` 周下载 **634**，是 D5 门槛（≥20）的 30 倍 | `api.npmjs.org/downloads/point/last-week/dsh-triage` |
| 但按天序列是 `0 0 0 0 0 0 0 / 634 / 0`（2026-10-22..10-30） | 同 API 的 `downloads/range` |
| 上游 `latest` = `next` = **0.2.1-rc.5**，而 README 首屏的卡片指着从未发布过的 `0.3.0` | `registry.npmjs.org/-/package/@deepseek-ai/dsh/dist-tags` |
| D5 的另外两个数（reactions / 外部引用）结构性地是 0：一份样本都没发过 | `docs/BACKLOG.md` `T-802` / `T-810` 均为 ⬜ |

如果照原样读周合计，D5 会得到**假通过**——而这个门是唯一决定「这东西要不要继续做」的门。

## 4. 对抗性（专门去找「这个门能被骗过去吗」）

| 反例 | 结果 |
|---|---|
| 读周合计 634 ≥ 20，判 D5 通过 | 被拒：`d5.counts_as_demand = false`，且单测把这条误读钉成断言（`total ≥ 20` 为真但不算需求） |
| 把 634 标成 `steady` | 被拒：形状由日序列算，`peak_share = 1` |
| 让规则「永远说不」以求安全 | 被拒：`tests/governance/market-baseline.test.ts` 的反向对照要求 steady 25 **必须**通过 |
| 把「没读出序列」写成「没有需求」 | 被拒：`unreadable` → `unmeasurable`（不是结论） |
| 把 429 响应当 fixture 缓存，让离线复算重放失败 | 被拒：只有 200/404 写 fixture（红产物 `05-30` 是修前的见证） |
| GitHub 403 时把 `threads: 0` 写成「没人有问题」 | 被拒：读不到讨论 → exit 2 且零产物；离线空 projection 同样拒绝（红产物 `06-20` 是修前的见证） |
| 在草稿里登记一个正文没提到的产物充数 | 被拒：定向负对照 `listing-2026-10-31T10-50-00.000Z.json` |
| 手改 README 卡片数字不重跑 | 被拒：`readme-shows-real-card` 从被引用产物读 `inputs.counts` 比对（R48 已有两条红产物） |

## 5. 留下的东西（写清楚，不要当成已完成）

1. **`BS-48` 仍 open**：形状能排除「单日爬虫」，排除不了「稳态的 20 次也是机器」；那一天的抓取方我们只有形状、没有归属；品类天花板同样只到「周合计 + 形状」。
2. **D5 的另外两个数还是 0**：草稿写好了，但一份都没发（`registry.json` 全部 `draft`）。窗口约到 2026-11-13。
3. **`0.3.1` 未发**：设置页那一屏仍只在仓里（`T-820`）。
4. **卡片的数字「换了目标没变」**：`--to 0.3.0` 与 `--to 0.2.1-rc.5` 都是 119/73/0/0，因为两个目标都在 rc.4 的精确钉定区间外。对外只能说「升级到 rc.5 时，声明层会拒掉 119 个单元」，不能说「新目标带来了新发现」。
5. **本轮没有 verifier 独立复算**：复算是我自己跑的（离线逐字节相同 + 4 条端到端测试）。按流程分级，交付轮要求「1 个 verifier 复算」——这一条留给下一位用产物独立重算（命令见 §2 与 `HANDOFF` §3）。
