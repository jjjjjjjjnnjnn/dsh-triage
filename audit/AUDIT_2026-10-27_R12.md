## 4. 四轴审核

### 4.1 正确性

- **主表一字未动**：`phaseConclusion` 的映射与 R7 相同；preset 判法是**新增**的一节（§3.1），因为它面对的是不同的上游语义（`null` 也覆盖「没有会话组合过」）。
- **不猜归属**：id 解析顺序是「精确 → 唯一后缀（**且同包**）→ 歧义即 `unknown`」；`resolveRuntimeId` 的返回类型让「挑一个」在编译期就写不出来。同包约束是复核 M3 加上的：只比 id 时，声明 `tools` 会被一条 `other:tools`（`@other/pkg`）满足，真缺失被抵消成「一切正常」。
- **不吞证据**：preset `broken` 仍列出并出 `unknown`（带原因）；`enabled: false` 的 preset 行**故意不出 verdict**，但仍在 `--json` 与 preset 段里可见——这是与主表 `runtime.disabled` 的刻意差异，理由写进 spec §3.1。
- **传输诚实**：`transport` 写在快照内部（`audit --snapshot` 直接读得到）、出现在产物与 CLI 头部、决定证据 `method`；未知值拒绝解析；未声明时**不借用** Remote 端点名。

### 4.2 可复现

- 采样脚本自带 stamp 校验（ISO-8601），产物内容不含墙钟（只有 `wait_ms`/`seconds` 这类**测量值**）。
- 合成样本可被任何人重放：夹具 `data/fixtures/inventory/desktop-web-2026-10-26.json` + 最小 profile `tests/fixtures/env/home/profiles/desktop/package.json`（本轮补，因为原命令指向的临时 home 已不存在）。
- 真机样本**不能**在别的机器上逐字节重放（它依赖沙盒与 boot 时序），产物因此把 `host.log_sha256`、`seconds`、`wait_ms` 一并记下，让「同一环境再跑一次」可比对。

### 4.3 合规 / 许可

- 未引入任何上游源码文件；探针只 `import` 上游已安装的 `@deepseek-ai/dsh-host-plugin-inventory`（MIT），通过 `createRequire(resolveFrom)` 指向**运行中的那条树**，不 vendor、不改上游。
- 不读凭据、不写 `~/.dsh`、不联网。

### 4.4 SSOT

- `data/results/inventory-live-*.json` 有 `produced_by` / `generated_at` / `schema_version` / `.sha256`（纯 hash）。
- `inventory-2026-10-27T00-00-00.000Z.json` 重放后 sha256 已同步进 `audit/step_reviews.json`（R7-S1/S2/S3 三处），并在 `outcome` 里写了「R12 重放，夹具未改」。
- `step-review` 门：R12 五个步骤各有一条记录（含 real_test 产物 sha256）。

## 6. 本轮的真 bug（值得单独记）

### 6.1 `dsh.bundle.patch` 的数组形态被静默丢弃

- **表现**：`audit` 在沙盒 profile 上只看到 `@deepseek-ai/dsh-base` 一层（96 行），`dsh-web-app` 整层凭空消失，且 `errors[]` 是空的。
- **根因**：`readBundlePatchPath` 只处理 `typeof patch === 'string'`；上游 `dsh-web-app` 用的是**数组**（`cordis.patch.yml` + 4 个 `presets/*.yml`），于是返回 `null`，调用方把它当成「这个 bundle 没有 patch 层」。
- **修法**：`readBundlePatchPaths`（字符串或数组）+ `declaresBundlePatch`（字段存在但畸形 → 报错，而不是空层）+ `patchScopeOf`（`presets/` 下的文件是 preset 组合，同时仍贡献 loader 载体行）。
- **效果**：真机 `undeclared` 195 → 3。

### 6.2 loader 运行时 id 带 group 前缀

- **表现**：健康 Host 上 96 条「声明了但不在」+ 195 条「在跑但没人声明」。
- **根因**：loader 把 profile 的 `cordis.yml` 包在 `include` group 里，行 id 变成 `include:<rowId>`；静态侧读的是 patch 里的裸 `<rowId>`。
- **修法**：`indexRuntimeIds` + `resolveRuntimeId`（精确优先 → 唯一后缀 → 多候选 `runtime.ambiguous-entry`）。
- **效果**：`missing` 96 → 0。

> 这两条都不是「新功能」，而是**既有结论在真机上是错的**。它们只有靠真机样本才能暴露——这正是本轮把 P1 排在 T-202/T-105 前面的理由。
