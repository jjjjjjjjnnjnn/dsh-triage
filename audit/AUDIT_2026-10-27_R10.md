# AUDIT · R10（2026-10-27）—— 让版本信号说真话：dist-tag 失步 + 区间形状

> 批次：R10｜范围：T-109 / T-115 + 新命名空间 `registry.*` + `scripts/record_registry.mjs`｜产物：`data/results/registry-2026-10-27T19-00-00.000Z.json`、`gates-*`、`gates-mutate-*`

## 1. 为什么先做这个（不是「加功能」）

`check` 之前只回答「声明区间 vs 你这台机器的运行时」。但 CASE-10849 / CASE-10201 的失败点**更早一步**：用户 `install <name>` 装到的是 `latest` 标签指向的旧构建，然后才被 admission 拒掉。工具说「声明不合」，用户听到的是「这个插件不能用」——实际是「你装错了版本」。这是判断层最常见的错位：**解释错了一层**。

同时补上 T-115：区间形状预测下一次失败。精确钉定（`0.2.1-rc.2`）会被上游下一次 patch 打挂；无上界（`*`、裸 `>=0.2.0`）会静默放大版本。两条都只提示，不改结论。

## 3. 对抗性反例（每条都真跑在单测里）

| # | 反例 | 结果 |
|---|---|---|
| 1 | `latest` 是稳定版、更新的只是预发布 | `prerelease-ahead`，**不算**失步（否则会冤枉所有发预发布的包） |

| 5 | `latest` 缺失 / 不是合法版本 / 一个版本都没有 | `latest-missing` / `unknown` / `unknown`，不猜 |

## 4. 本轮**没有**解决的

| 项 | 现在的真实状态 |
|---|---|
| 「为什么」tag 是旧的 | 只能说「标签旧了」，不能推断是忘了打标签还是故意留旧版本（后者在 rc 生态里确实存在） |
| 最新 ≠ 能用 | registry 事实不参与结论：`latest-behind` 只说明「你可能装到旧版本」，能不能跑仍由声明层（和 M3 probe）回答 |
| webhook / 时间序列 | 本轮是**快照**：只能回答「打这个 stamp 时是旧的」，回答不了「什么时候开始旧的」 |
| `deprecated` 的语义 | 只做排除，以及「tag 指向被弃用构建」的提示；不解释弃用原因（那是作者侧信息，我们没有权威来源） |
| 通道粒度 | 只区分「稳定 / 预发布」，不细分 `rc` 与 `nightly`：`latest=1.0.0-rc.5` 遇到 `rc.6-nightly.*` 会被判落后（保守方向，见 `BS-18`） |
| T-113 / T-114 / T-117 | 未动 |

## 6. 诚实边界（三句）

1. 「三个包的 `latest` 都落后」≠「这三个包不能用」。它只说明**装裸包名会拿到旧构建**。
2. 「`--explain` 显示的 `next` 是最新」≠「`next` 可以装」。`next` 是频道名，不是兼容性承诺。
3. 「区间形状建议」是**作者侧**建议，不是用户侧结论；`check` 只是顺手把它说出来。

## 7. 独立对抗性复核（只读上下文，未看实现过程）

会话 `ses_e83ed6025ffeyZdwrE17QZ3ITx` 判定 **PARTLY CONFIRMED**，抓出 4 个必须当场修的洞，修复后全部复核成立：

| # | 复核发现 | 处置 |
|---|---|---|
| 1 | `=1.2.3` 与精确版并集（`1.2.3 \|\| 4.5.6`）被 `EXACT_VERSION` 漏掉、落到 `validRange` 后无 `<` → 判成 `unbounded`，于是对「根本不会漂移」的声明发出「无上界会被静默放大」的**假警告** | `judgeRangeShape` 先剥 `=` 前缀再判 exact；并集逐臂判定时把「精确版本臂」视作有界 |
| 2 | `latest` 指向**未发布**版本时输出 `none` + 「指向最新已发布」——可证伪的假话（`install <name>` 根本解析不出来） | 新增 `latest-unpublished`（warn）与文案；同时补 `latest-deprecated`（tag 指向被弃用构建） |
| 3 | `deprecated: ""` 被当成「已弃用」；而 npm `deprecate pkg@v ""` 正是**解除**弃用 → 漏报失步 | `parsePackument` 改为「非空字符串才算弃用」，并加单测 |
| 4 | 终端渲染按插入顺序切片：admitted 时前两条是 info，本轮头条 `registry.latest-behind` 被 `…2 more` 吞掉，默认输出**看不到** | `renderVerdict` 改为按 `block > warn > info` 稳定排序（`admission-row-scope` 仍钉最前），并加「头条必须出现在前三条」的断言 |

复核同时纠正 4 处口径（已改文档/台账）：测试数 119→124、`docs/05` 「区间形状只在 `--explain` 出现」与代码相反（实际 `check` 始终带）、「同通道比较」名不副实（只分稳定/预发布，不细分 rc 与 nightly）、`BS-18` 漏记「tag 指向弃用构建」这一类边界。
