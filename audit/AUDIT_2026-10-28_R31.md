## 2. T-401：真机注册通过（两处真实发现）

| # | 步骤 | 结果 |
|---|---|---|
| 1 | 把四个 workspace 包按 `file:` 装进一次性 DSH home（不碰 registry、不碰凭据） | exit 0（20.4s，pnpm 没有下载任何东西） |
| 2 | 起真 Host | 打印 `http://127.0.0.1:<port>/` |
| 3 | 读启动文档（token 303 → cookie → `/`） | **图里出现了 `dsh-triage/client.js`** |
| 4 | 取组合 URL（`/plugins/??<ids>/client.js&rev=…`） | **200 / 2,020,463B / 含 `__ModuleLoader__.load` / 含 `id: 'dsh-triage'` / 含 `settings.plugins.tab`** |
| 5 | 真浏览器（headless Chrome + CDP）打开页面，读 `window.__dshTriage` | **`{registered:true, slot:'settings.plugins.tab', id:'compat-triage'}`** |
| 6 | 清理 | 通过（Host 先杀再删；R31 前几轮都是先删后杀，EPERM 连环失败） |

产物：`data/results/client-serve-2026-10-28T19-20-00.000Z.json`（`scripts/record_client_serve.mjs`）。

**两处只有真机才暴露的契约细节**（光读源码会写错）：

- **`package.json#exports["./client"]` 是必需的**：`dsh-client-modules` 用 `clientExportOf()` 取它，缺了就抛 `declares dsh.client but exports no "./client" bundle`，模块被**静默丢弃**（页面里根本没有它）；
- **profile patch 行的 `name` 必须是裸包名**（`dsh-triage`），不能是子路径（`dsh-triage/host`）：`exactPackageSpecifier()` 只接受裸名，子路径会让 `locatePkgJson()` 返回 `undefined` → 浏览器半边永远不被组进图。R30 的 `cordis.patch.yml` 用的正是子路径，所以**即使 bundle 装上了、host 半边也 dump 出来了，client 模块仍然不存在**。修法：行名改成 `dsh-triage`，并让 `dist/index.js` 重新导出 host 插件（`apply` / `name` / default），保持程序化 barrel 不变；
- **资产 URL 带 `?rev=`**：`/plugins/<pkg>/client.js` 裸请求一律 404，必须用启动文档里给出的组合 URL。R31 前 6 次尝试全栽在这一点上。

**仍未做**：设置页里**肉眼看到**那个 tab（要点击导航后断言 DOM），以及「tab 内容与 CLI 同源」（要 Host 侧一条只读 Remote）。产物里的 `mount` 步骤证明的是「注册被真机接受」，不证明「用户点开设置就能看到」。

## 3. T-315：布局收口（含更正 R30）

| 路径 | `node_layout` | 说明 |
|---|---|---|
| 模板 profile + 仓内候选 | `linker=hoisted, declared=hoisted, top_level=1, top_level_symlink=true, virtual_store_links=0` | 那个 symlink 是 `file:` 候选本身，**不是**存储链接 |
| `nodeLinker: hoisted` 的复制源 | `linker=hoisted, declared=hoisted, top_level=195, virtual_store_links=0` | 真的切到了 hoisted：195 个平铺包 |

产物：`data/results/probe-ok-2026-10-28T14-40-00.000Z.json` · `data/results/probe-t315-hoisted-2026-10-28T14-50-00.000Z.json`。

**R30 的读数作废**（`BS-34`）：`.pnpm` 在两种布局下都存在，不能当判据；`.modules.yaml` 是带引号的 JSON 风格，严格 YAML 正则读不到；第一个顶层条目是 `file:` 候选链接时会把 hoisted 读成 isolated。三条叠加时，**一个自信但错误的方向**就进了产物。R31 改为「pnpm 自己写的 `nodeLinker` 为准 + 回退时只数指向 `.pnpm` 的链接」，并同时发布 `top_level_symlink` / `virtual_store_links` / `pnpm_store` 三个事实。

**结论**：R26 的 F49「hoisted 不会打断候选行识别」现在有布局读数支撑——那次跑的是复制源，本轮同一形状实测 `top_level=195` 的 hoisted 树仍然 `go`。**仍缺**：`strictPeerDependencies` 等其它可继承设置未逐一实测。

## 5. 对抗性

| 反例 | 结果 |
|---|---|
| 「三批都绿，`BS-32` 可以关」 | 不关。三批是**同一台空载机**；R27 的 22.5s 出现在并发负载下，且两者**口径不同**（最终样本 vs 第一份）。对外只给区间，不承诺秒数 |
| 「p90 8.2s，那就写『probe 8 秒』」 | 不许。p90 是这批 36 次观测的分位数，不是承诺；`limits[]` 已写死「a low p90 does not promise anything about the next run」 |
| 「`mount` 通过 = 用户能在设置页看到 tab」 | 不是。`mount` 证明 client runner 调了 `apply`、slot 接受了注册；**肉眼可见**要点击导航后断言 DOM，本轮没做 |
| 「`client.js` 服务 200 就说明契约都对」 | 反例已实测：200 之前有两处静默失败（缺 `exports["./client"]`、行名用子路径），页面里连模块都没有。所以脚本先断言**启动图里有没有它**，再看资产 |
| 「布局读数改一次就够了」 | R30 就是这么想的，然后给出了相反的方向。所以本轮加了两条真机对照（模板 vs hoisted 复制源）+ 6 条单测，并把 `.pnpm` 降级为提示位 |
| 「删掉的 11 份失败产物是销毁证据」 | 它们在**同一个脚本的调试迭代**里，且失败原因（404 路径猜测、缺 exports、子路径行名、先删后杀）已写进本报告与 `BS-34`/`BS-35` 的正文。真跑结论只留最终全绿那份，避免把调试噪音混进 SSOT |

## 7. 口径

> **稳定性**：同一 plan 连跑三批，真实 36 次观测 `boot→sample` **3.5–9.6s（median 5.4s，p90 8.2s）**，0/36 超 20s，三批结论一致。**不许**说「probe 稳定在 X 秒」；**不许**把 R27 的 22.5s 与本轮的 6.6s 直接相减（口径不同）。
> **T-401**：「Host 会把 `dsh-triage/client.js` 组进启动图并服务；真浏览器里 tab 注册被接受」——到此为止。**不许**说「设置面板已经在 DSH 里可见」，也**不许**说「结论与 CLI 同源」。
> **T-315**：布局是观测（`linker`），配置是自述（`declared`）；两种布局都有 `.pnpm`，所以它只是提示位。R30 那份 `isolated` 读数作废。
