## 3. 三条硬边界（本轮的核心产出）

| # | 边界 | 怎么证的 |
|---|---|---|
| B1 | 插件不静态声明工具名 | 读 `dsh-tool-bash` / `dsh-tool-fs` / `dsh-plugin-manager` / `dsh-skill-filesystem` 的 `package.json`：无 `dsh` 字段；`bash`/`read`/`write`/`edit`/`read_image` 只出现在构建产物里 |
| B2 | 工具注册在 agent/preset 作用域 | 真机两次采样（基线 / 禁用 `tool-fs`）都只有 1 个工具 `working_directory`；preset 里 `tool-bash` 等行是 `active` 却不在清单里 |
| B3 | `ptc` 折叠可见面 | 不强制 native 时 `schemas()` 仅 `run_code`；`presentAs('native')` 是公开 API，但只影响调用者 scope，不改变注册表 |

**因此**：本层交付「事实 + 差分 + 边界」，不交付「缺失工具」结论。产物里 `outcome=expectation-not-met` 就是这条结论的机器可读形式。

## 5. 四轴

### 5.1 正确性

- 没有判据就**不产出 verdict**：本轮不新增 `runtime.*` / `capability.*` 命名空间，避免出现「有结论、没依据」的卡。
- 三处诚实字段：`registry: null`（无服务）≠ `tools: []`（有服务但空）；`read_error`（读失败原因）≠ 空清单；`presentation`（在哪种呈现下读的）必须记录，否则「只有 1 个工具」会被误读成部署没装工具。
- T-105：`audit` 与 `why` 用同一个 `verdictsFromRowAdmission` 与同一批 `resolveRows` 结果；`unknown` 不计入失败与 `why` 的默认行为一致（只有 `--strict` 才失败），并把这条差异写进代码注释。

### 5.2 可复现

- 能力层解析/差分是纯函数；单测 6 条。
- 两个 live 记录器共用 `scripts/lib/live.mjs`（本轮为此把 R12 的实现抽出来），避免两份 boot 逻辑漂移。合并时抓到两个自己写的真缺陷：重复写了 `profile` 导致 overlay YAML 出现重复 key（`dsh` 直接解析失败）、删掉 `spawnSync` 后交叉校验段仍在用它——都靠真跑抓到（S6）。
- 因果实验的 overlay 由参数生成：`--disable <patch-row-id>`，产物同时记 patch id 与运行时 id。

### 5.3 合规 / 许可

- 只读上游已安装产物（MIT）与自有代码；不 vendor、不复制实现；不写 `~/.dsh`；不联网。

### 5.4 SSOT

- `capabilities-*.json` 带 `produced_by` / `generated_at` / `schema_version` + 纯 hash `.sha256`；边界三条写在产物 `boundary` 里。
- `inventory-live-*.json` 因 hook 扩容按同一 stamp 重采，R12 的步骤记录 hash 同步更新。
- `data/results` 57 步全被引用，无孤儿。

## 6. 对抗性（自己构造）

| # | 攻击 | 结果 |
|---|---|---|
| F1 | 把「没有工具服务」写成 `registry:'tools', tools:[]` | 单测红（两者必须可分） |
| F2 | 同一快照同名工具两次 | 拒绝解析（不得静默去重） |
| F3 | `schemas()` 抛错但清单为空 | `read_error` 非空 + 记录器 `registry-read` 判 blocker |
| F4 | 不 dispose `presentAs('native')` | 探针 scope 的呈现被永久改写 → 后续读被污染；现用 try/finally 释放 |
| F5 | 期望未达成时把产物标成 `sampled` | 记录器把它记成 `expectation-not-met` 且 exit 1（本轮就是这样产出的） |
| F6 | `audit` 只按 bundle 判 → 与 `why` 不一致 | e2e 交叉一致断言红 |
| F7 | 让 `unknown` 也计入 audit 失败 | 沙盒真机 profile 的 72 条 unconstrained 会让命令永远 exit 1（本轮实测后定规则） |
