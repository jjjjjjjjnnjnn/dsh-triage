## 1. 复审发现：两个候选缺陷，一个真、一个假

我先用真实取值去打 R64 新写的两条规则，而不是靠读代码下结论。

### 1.1 假缺陷（幸好先测了）

怀疑：X 平台的 channel 识别 `/(?:^|[^A-Za-z])x(?:\s|\/|$)|twitter/i` 会把 **`V2EX`** 误判成平台 X
（`V` `2` `E` `X` 里 `X` 前面若不是字母就会命中）。

实测：**不成立**——`V2EX` 里 `X` 前面是 `E`（字母），不命中；`V2EX · 程序员节点`、`V2EX 分享发现` 都判成「不是 X」。

**但这不是白做的**：它现在是一条回归测试（`tests/unit/posting.test.ts` 里的 `V2EX is not the platform X`），
因为下一次有人「顺手把正则放宽一点」就会踩到它。

### 1.2 真缺陷：`+01:00` 被拒，而且报错说的是假话

R64 的规则要求 `posted_on` 匹配 `/…(?:\.\d{1,3})?Z$/`，即**只认 `Z`**。于是：

| 输入 | R64 判定 | 事实 |
|---|---|---|
| `2026-11-02T17:36:00.000Z` | 通过 | 正确 |
| `2026-11-02T18:36:00+01:00` | **拒绝**，报「不是带时区」 | **假话**：`+01:00` 明确指定了时区，且 `Date.parse` 与上行**完全同值** |
| `2026-11-03T01:36:00+08:00` | 拒绝（同上） | 同上 |
| `2026-11-02` | 拒绝 | 正确（会被当 UTC 零点，窗口挪最多 24 小时） |

这条不是理论问题：**这台机器就是 UTC+1**，本轮的 `posted_on` 就是从这个时钟换算出来的；下一位 HUMAN
（或下一个 agent）按本地时间写 `+01:00` 是最自然的动作，而现在会被拦下并看到一个错误的原因。

**修法**：把规则抽成纯函数 `scripts/lib/posting.mjs#judgePosting()`，接受 `Z` 或 `±hh:mm`，
仍然拒绝裸日期与未来时间；`check_listing` 只负责把问题串加上文件名前缀。
抽出纯函数不是为了好看——**这条规则三轮里错了两次**（R56 只认 discussion；R64 只认 `Z`），
每次都是「匹配器」错，而匹配器以前只能靠端到端跑才能碰到。

## 2. 四条控制（全部真跑，全部保留产物）

`posted_on` / `posted_url` / `channel` 三者各构造一种状态，跑真检查器，跑完**立刻写回原串并复算 sha256**。

| 产物 | 构造 | 期望 | 实得 |
|---|---|---|---|
| `listing-2026-11-02T18-20-00.000Z.json` | `posted_on = 2026-11-02T18:36:00+01:00` | **绿**（修复的正面证明） | `exit 0` · 15/15 绿 |
| `listing-2026-11-02T18-25-00.000Z.json` | `posted_on = 2026-11-02` | 红 | `is not an ISO-8601 instant with an explicit zone … use Z or ±hh:mm` |
| `listing-2026-11-02T18-30-00.000Z.json` | `posted_on = 2026-12-01T00:00:00.000Z` | 红 | `posted_on is in the future` |
| `listing-2026-11-02T18-35-00.000Z.json` | X 的 URL + GitHub Discussions 的 channel | 红 | `posted_url is not a github-discussion URL` |

**新增一条可审计的元数据**：`check_listing` 的产物现在记 `inputs.drafts_registry_sha256`。
因为控制是「改 → 跑 → 还原」，没有这个摘要的话，五份产物看起来都只是「15/15」，审计时无法知道
**当时检查的是哪个状态**。实测：正面控制 `12632ca8…` / 终跑 `42ab4db9…`，两个值不同，说明它真的在区分。

## 4. 复审里又抓到一次「同一族的 bug」

`record_usability_smoke.mjs` 第一次跑完，输出写着 `ssot data/results/usability-…`，而**文件其实落在 `--out`
指定的目录**——我把 R64 在 `watch_next_release.mjs` 里刚修过的「硬编码打印路径」又抄了一遍。
发现方式：负对照用 `--out %TEMP%`，打印路径与落盘目录不一致。已改成打印真实目标路径。

**同一个 bug 一天内被抄了两次**，说明「记录器的输出」也需要一条机器校验。这条记为待办（见 §6）。
