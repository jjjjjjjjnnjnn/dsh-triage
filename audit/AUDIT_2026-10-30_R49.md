## 3. 三个真发现（都是「看起来是绿的」假象）

1. **CSP 把自己的页面打死了**：`default-src 'none'` 同样管辖 `connect-src`，页面里的 `fetch('/api/artifacts')` 全部被浏览器拦掉。旧面板**在真浏览器里从来没有加载出过产物表**，但 `record_serve_smoke.mjs` 的注释写着 `no browser is involved`，17 项 HTTP 冒烟全绿。→ 加 `connect-src 'self'` + 一条回归测试（断言没有通配符、`default-src` 仍是 `none`）。
2. **空组合被判成「没有问题」**：`claims.length === 0` 时所有计数都是 0，tone 落到 `ok`。这是「用空集合冒充通过」，与「空账渲染成干净审计」是同一个错误。→ 0 行 → `attention` + 明确指向参数。
3. **列表路由整份读入任意大小的 JSON**：`/api/artifacts` 对每个文件 `JSON.parse(readFileSync(...))`，只有详情路由有 2MB 上限。data/results 里放一个大文件就能把面板拖死。→ 列表也只解析 ≤2MB 的文件，超限的仍然列名字（`conclusion: null`）。

## 5. 对抗性反例（我自己先试的三种「骗过门」的办法）

1. **只跑 `--fast` 就宣布全绿** —— 被拒：需要构建产物的门被跳过，本轮判据是完整套件 + `--mutate`。
2. **在测试里 mock 掉 `fetch` 证明面板能用** —— 被拒：那正是旧冒烟脚本的错（`no browser is involved`）；本轮用 Edge headless 真截图看首屏与证据页签。
3. **把「154 行没声明」写成「154 行正常」以让计数好看** —— 被拒：这正是要修的谎；摘要里那 154 必须是独立的一句，且不进 `go` 计数。

## 6. 明确没做 / 没测（诚实边界）

- **没做**：`--allow-execute` 仍只到 501（从浏览器跑 probe 是 M4-a）；面板没有速率限制；没做 `Host` 头校验（见 `docs/SECURITY.md` §4.2）。
- **没测**：Firefox / Safari 的真实渲染（只用 Edge headless 验过）；移动端视口；`--host 0.0.0.0` 的行为（不建议使用，也未测）。
- **未发布**：`0.3.0` 已在本轮之前的 R48 就绪，`npm publish` 需要 HUMAN 本机交互输入 OTP。

## 7. 反思

- 「API 冒烟全绿」不等于「页面能用」：一个 `default-src` 就能让面板在真浏览器里永远空白而不报任何 HTTP 错误。以后**改面板必须至少截一张图**（已写进 `docs/SECURITY.md` §6）。
- 我们最擅长的错误是「把沉默当通过」：空组合、未声明行、关闭的路由，三种「没看见」都可能被渲染成「干净」。这次的修法不是加文案，而是让**状态码/横幅/计数**三者都可区分。
- 交付轮降的是审核成本，不是证据：本轮没有四轴并行评审，但有 1 份真跑产物 + 1 次独立复算 + 轮末一条汇总台账。

## 8. 第二轮（同日）：用户反馈「不一目了然 / 没有清爽的 UI」

**背景**：第一轮把「一屏答案」做出来了，但用户仍然觉得「不容易查看和控制」。加上用户在仓根执行
`npm publish` 拿到 `EPRIVATE`（根 `package.json` 是工作区根，本来就该 private）。

**做的两件事**：

1. **发布入口写清楚**：根 `package.json` 增加 `"release:publish": "pnpm -r publish --access public"`。
   正确入口从来不是 `npm publish`（在仓根），而是 `pnpm -r publish`——只有 `pnpm publish` / `pnpm pack`
   会把 `workspace:*` 改写成具体版本（实测 `dsh-triage-0.3.0.tgz` 的 `dependencies` 是 `0.3.0`，不是 `workspace:*`）。
2. **面板从「能读」做到「能操作」**：搜索 / 类型 / 结论三个筛选、六列可排序表头、右侧详情抽屉
   （复制名称 / sha256 / JSON）、「复制这段结论」、六个可点计数（点了就筛「要看的地方」）、
   主题三态、快捷键、`#artifact=` / `#theme=` 深链。

**两处真发现的界面缺陷**（都不会让任何 HTTP 断言变红）：

| 缺陷 | 症状 | 根因 | 修法 |
|---|---|---|---|
| 注入的文案表漏了 3 个键 | 两个下拉框空白、快捷键提示空白；第一张截图「看起来干净」 | 页面读 `COPY.allKinds` / `COPY.allConclusions` / `COPY.kbdHint`，但注入的 JSON 里没有 → `esc(undefined)` 给空串 | 补齐注入；新增**结构性测试**：抓出页面里所有 `COPY.<key>` 读法与注入表逐个比对，缺一个即红 |
| 浅色主题的画布仍是深色 | 白卡片浮在黑底上，像「半坏」 | `color-scheme: light dark` 让 canvas 跟随系统（本机深色），而 `--bg` 已切成浅色 | 每套主题各自钉 `color-scheme`，并显式给 `html` 上背景 |

**结论列也修了**：录法不统一（`passed` / `ok` / `expectation_met`），原来只读 `conclusion`，导致
252 份产物里约 200 份显示「没有结论」——现在三种都读得出，且 `false` 老实显示「失败」。

**证据**：`data/results/serve-smoke-2026-10-30T11-40-00.000Z.json`（18/18，新增 `page-controls`）·
482 测试 · 4 张真浏览器截图（深色首屏 / 深色证据页 / 详情抽屉 / 浅色首屏）。

**没做**：面板仍然只读（`POST` 仍 403/501），没有做「删除产物 / 重跑探测」这类写操作——那是 M4-a，
需要单独的授权与威胁模型；Firefox / Safari 仍无见证（`BS-46`）。

## 9. 第三轮（同日）：用户说「看不懂，普通人也要能用」

**背景**：第二轮把面板做成可操作的（搜索 / 筛选 / 抽屉），但第一屏仍然是给工程师看的：
「156 行（2 行有判定）· 其余 154 行不声明任何 DSH 区间」。同时用户按 `pnpm -r publish` 拿到 404。

**发布那个 404 不是包不存在**：`npm whoami` 返回 401 —— npm 登录已失效。未登录时对 scoped 包
发布会回 404 而不是 401，这是 npm 的行为，不是我们的。修法有两层：

1. 四个包加 `publishConfig.access=public`（scoped 包默认按私有发布，私有要付费组织）；
2. 新增 `scripts/release_preflight.mjs`：登录 / 四包同版本 / 可见性 / 是否 build，逐项给人话，
   把 404 直接翻成「你还没登录：`npm login`」。`pnpm run release:publish` 会先跑它。

**面板改成「傻瓜模式」**：

| 之前 | 现在（默认） |
|---|---|
| 「156 行（2 行有判定）· 0 正常 · 0 被拒 · 2 判不了」 | 「没有会坏的东西，但有 2 项我们判断不了，通常不影响启动。」 |
| 每条问题是引擎的 reason 原文 | 每条问题一句人话（「它没说自己支持哪个版本，所以我们判断不了」） |
| 用户要自己决定下一步 | 一个主按钮：有修复命令就「复制修复命令」，否则「复制这份结果」 |
| 表格与筛选是第一屏 | 第一屏只有结论与按钮；右上角 `简单 / 详细` 一键切到完整 UI |

**关键的诚实性约束**（都有测试）：`plain` 在 `tone` 非 ok 时**禁止**出现「一切正常 / All good」；
每条问题的 `plain` 必须与 `line` 不同且不含 `admission` / `peer` / `entry id` 术语；154 行未声明在
简单模式里**仍然要说出来**，只是换成「另外 154 个插件没说自己支持哪些版本，我们判断不了（这不等于
它们没问题）」。**简单 = 换一种说法，不是删掉证据。**

**证据**：`data/results/serve-smoke-2026-10-30T12-10-00.000Z.json`（18/18，8 个控件）· 484 测试 ·
简单模式浅色/深色各一张真浏览器截图。

**没做**：「自动执行修复」不做——面板只读，按钮只复制命令，不写用户的 profile（铁律 4）；
真要执行也是 M4-a 的独立授权项。
