## 2. 正确性

**PASS。** 三个可判定的断言：

1. **主导成本是替换等待，不是 settle**：`boot` 步 48384ms = sample 19128 + **替换等待 20276** + settle 1011 + readiness 36 + render 4502 + 杀树 2203 + 杀后 1215。
2. **缩短窗口不改变结论**：同一夹具 20000 / 5000 / 1000 三组全部 `unknown`；`boot` 步 48.4 / 33.9 / 26.2s，替换等待 20.3 / 5.3 / 1.2s，`measured_saving_ms = 19092`。
3. **替换从未在已记录证据里生效**：29 份有相位块的产物里，4 次不可判样本的 `attempts` 与 `applies` **全为 1**（`{error}` 形状出现 0 次）。

## 3. 可复现

**PASS。**

- 三组窗口：`node scripts/record_probe.mjs … --unsettled-timeout <ms> --stamp <iso>`（已发布参数，本轮没有新增开关）；
- 统计：`node scripts/report_replacement_window.mjs --stamp <iso>` —— 纯读已提交产物，不需要沙盒运行，退出即有 SSOT；
- ADR 里每个数字都能对应到上面两份产物中的一行。

## 4. 合规与许可

**PASS。**

- 只跑本地夹具，无外部候选、无 vendor 条目；
- **没有改任何阈值**：ADR 的签字区四项全空，正文写明「未勾选前一概不动」；
- 本轮不引入新的执行面（不批准构建、不注入凭据）。

## 5. SSOT 一致

**PASS。**

- `ADR-0008` ↔ `spec §4` ↔ `BACKLOG` T-311/T-312 三处指向同一份替换统计；
- 114 份产物 / 129 步台账全部可追；`HANDOFF` §2 的数字（265 测试 / 114 产物 / 129 步）来自 `pnpm test` 与台账本身；
- ADR-0006 的「可判 ≈16s / 不可判 ≈48s」与 ADR-0008 的成本表使用同一套读数。

## 6. 对抗性（本轮真的会错的地方）

| # | 注入/反问 | 结果 |
|---|---|---|
| A1 | **「窗口省了 22s」** | 反例成立：1s 那一轮 `url_seen=false`，render 被跳过（`renderMs=0`），所以不能把 48.4−26.2 全算成窗口收益。按 5s 那轮补正后是 48.4−33.9 = **14.5s**，ADR 写的是区间 15–20s 与报告的 19.1s（同夹具同形状的真实差值） |
| A2 | **「历史没出现替换 ⇒ 窗口无用」** | 反例部分成立：这只是「已记录证据里没有」，而 R17 的机制是**开发期**观察到的，产物里未必留痕（旧产物还没有 `attempts`/`applies` 字段）。ADR 的 `limits[]` 与正文都写了这条 |
| A3 | **「顺手把默认值降到 5s，反正更快」** | 反例成立：这是阈值变更，需 ADR + HUMAN-SIGN（铁律 4）。本轮所有运行都显式传 `--unsettled-timeout`，默认值一行未改 |
| A4 | **「E 案等于去掉恢复路径」** | 反例不成立：E 只对 `settled:false` 停止等待，`{error}`（dead context 被新 apply 取代那条，正是 R17 的理由）仍等满 |
| A5 | **「用 `undefined !== null` 判断不可判」** | 反例成立：第一版临时统计因此把 13 份旧产物算成不可判；正式脚本显式归一为 `null`，并把旧产物单列为 `without_shape_fields=16` |
