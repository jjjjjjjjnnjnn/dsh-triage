## 1. `T-501`：0 PII 是被执行的，不是被声明的

**判据先行**：`docs/specs/M5-reflow.md` 在写代码前就钉死了字段白名单、黑名单、存储路径与 14 条负对照；
`ADR-0011` 把「先验能不能改结论」写成 A/B/C 三案。HUMAN 原话「你自己分析研究进行，我全部同意」→
按 A 案代签（先验只做 `check --explain` 的注解，永不进 `conclusion`），并据此把 D4 从
「命中率差 ≥10pp」改成「先验与后测的一致率」——原判据结构上不可测，因为先验不许改结论。

**实现**（`packages/core/src/outcome.ts` + `packages/plugin/src/outcomes/*`）：

| 要求 | 怎么被强制执行 |
|---|---|
| 0 PII | 白名单投影（多一个键**整条拒绝**，不修复）+ 值域 + 路径/令牌形状扫描 + 1024B/行；夹具由门 `outcome-privacy` 用运行期 sanitizer 逐行校验 |
| 默认关闭 | 关闭时**不建目录、不建文件、不 touch mtime**（用 sha256 + mtime 双证，N1/N4） |
| 删除 | `outcomes --purge` 只删自己拥有的文件；删完 `remaining=[]`、目录移除；重复执行是 no-op（N5/N6） |
| 先验 | 只出现在 `check --explain` 的**兄弟键**；`check --json` 在有/无先验下**逐字节相同**（N3，两个 payload 哈希 `7b0948cf…`） |
| 本地零网络 | 门按源码扫描 `fetch(` / `node:http` 等；`--mutate` 与真实注入各验一次（N12） |

**真跑**：`data/results/outcomes-2026-10-30T01-10-00.000Z.json`（`d721c455…`，24/24）——4 条记录
（check 3 / probe 1）→ purge 删 4 条、目录移除、`remaining=[]`；记录 401–442B。

## 2. `T-502`：四桶是分区，registry 不能搬桶

**判据**：`dsh-triage upgrade --to <version>` 把 `evaluateAdmission` 的 runtime 换成目标版本
（**没有第二套区间规则**），每个单元（bundle 或 loader row）恰好落一个桶：
`would-be-denied` / `cannot-tell` / `improved` / `likely-fine`，`total = bundles + rows`。
`reasons`/`remediation` 直接取 `verdictsFromRowAdmission` / `verdictFromAdmission`，与 `why` 同源。

**registry 只是注解**：`registryFactFor` 用同一个 `evaluateAdmission` 选版本，注解在**分桶之后**挂上——
「注解影响分桶」在结构上不可能发生，而不是靠约定。真机把代理指到死端口：12 次查询全失败、192 个单元
逐条不变、exit 0。

**真机**（`data/results/upgrade-2026-10-30T03-40-00.000Z.json`，`ce800146…`，26/26）：
192 单元 = 2 bundle + 190 row；**119 拒 / 73 不可判 / 0 改善 / 0 既有坏账**；同一批行
`--to 0.2.1-rc.4` 上 **0 拒**（对照，`target_change_moves_the_list`）；`why` 的 unknown 集合 72=72，
但产物自己写 `denied_comparison_vacuous: true`——空对空不算证明。

**它说不出什么**（`limits[]`）：没在 `0.3.0` 上启动过任何东西；离线所以没验证 `0.3.0` 是否存在；
只对这一个 profile / 这台机器成立；没装的东西没有答案。

**已知空洞**：`improved` 桶在真实组合上恒 0（沙盒里每个包都精确钉 `0.2.1-rc.4`），需要一份
混合声明的 profile 才有真机见证；`--registry` 的成功分支也没证据（那轮故意打不通）。

## 3. 两个版本：0.1.1（文档）与 0.2.0（功能）

| 版本 | 内容 | 验证 |
|---|---|---|
| `0.1.1` | 把重写后的 README 带上 npm 页面，行为与 0.1.0 相同 | `publish-2026-10-29T10-10-00.000Z.json`（19 项） |
| `0.2.0` | `outcomes` + `upgrade` + `check --explain` 的先验注解 | `publish-2026-10-30T05-00-00.000Z.json`（20 项） |

**这一轮最值钱的一次拦截**：准备 0.2.0 时只想升插件版本，在干净目录里装 tarball 真跑，直接炸：

```
SyntaxError: The requested module '@dsh-triage/core' does not provide an export named 'assertOutcomeLine'
```

`outcomes` 用的是 core 新增的导出，用户会装到 core@0.1.0 → CLI 一启动就崩。**这不是推理，是安装现场
抓到的。** 修法：四个包一起升 0.2.0、一起装、CLI 与 `upgrade` 都真跑，再走 `record_publish` 的
**匿名安装**复验（空 `userconfig`，装回来三个内部包都是 0.2.0、CLI 11 条命令）。

**顺带修掉的另一个错误假设**（R41）：`record_publish` 曾把 `--version` 当成所有包的版本；0.1.1
只升根包时它把自己判红。现在按根 manifest 的 `dependencies` 取期望版本。

## 4. 两次真实事故（都保留，不藏）

1. **home 路径进了产物**：`upgrade` 第一次真跑把 `--dsh-home` 的绝对路径写进 `runs[].command`，
   `gate_governance/results-privacy` 当场打红。处置：产物移出仓库、记录器改成 `command` 里写
   `<dsh-home>`，并且**写盘前扫自己生成的字节**，命中 home 形态直接 exit 2 不写。
2. **stamp 撞车**：R40 我两次用撞了历史时刻的 `--stamp`，把已引用的产物覆盖掉（症状只在事后以
   sha256 不匹配出现）。已给 `gate.mjs --record` 加**拒绝覆盖**（exit 2）+ e2e 测试；本轮两次录制
   都先查过 stamp。

## 5. 对抗性（自问自答）

- 「测试全绿」≠「行为没变」：`check`/`probe` 加了 `recordOutcomes` 之后重跑了 D2 矩阵（3.5–10.0s，
  12 go / 1 blocked，预算 12/12、可靠性 20/20、形状 6），确认没有漂。
- 「先验有用」≠「能提升命中率」：A 案下 `check --json` 逐字节不变，所以对外只能说注解。
- 「会被拒」≠「会坏」：`upgrade` 的 `limits[]` 明写没有在目标版本上启动任何东西。
- 「发布成功」≠「能装」：两个版本都用空 userconfig 装一遍并跑 CLI。
