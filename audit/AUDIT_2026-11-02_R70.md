## 1. B · 判定表第一行拆成两行（判据改动）

### 1.1 改之前错在哪

旧表第一行是「**没有 `posted_on` 或没有贴子 URL** → `no-post`」。当 URL 明明在手上、只是日期读不出时，
这句话是**假话**——工具会宣称「没人发帖」，而它正拿着那篇帖子的链接。

这是 R66/R67 那串修正的**最后一环**：R66 把日期校验挪到数据流上、R67 让 `windowOf` 拒绝不存在的时刻，
于是「窗口起点读不出」这件事第一次**能被表达出来**，而它当时被塞进了 `no-post` 这个错误的桶。

### 1.2 改成什么

| 条件 | `verdict` | `reason` |
|---|---|---|
| **没有贴子 URL**（真的没发） | `no-post` | `null` |
| **有 URL，但 `posted_on` 读不出**（缺失 / `2026-02-30` / 非 instant） | `unmeasurable` | `window-start-unreadable` |
| 任一数 `unreadable` | `unmeasurable` | `number-unreadable` |
| 三个数达标 | `pass` | `null` |
| 窗口未结束、未全达标 | `pending` | `null` |
| 窗口已结束、至少一个未达标 | `fail` | `null` |

**为什么用 `unmeasurable` 而不是 `fail`**：`fail` 是关于产物的结论，而这里我们对产物一无所知。
按仓里反复付学费的那条铁律——「读不到 ≠ 观察到没有」（`BS-48`）——只能 `unmeasurable`。

### 1.3 证据

- 单测 N2 改期望（`no-post` → `unmeasurable`）+ 新增 **N2b**（完全没有帖子 → 仍是 `no-post`）+ N8 同步；
  `tests/unit/d5-score.test.ts` **11 条全过**。
- spec `docs/specs/D5-measurement.md` §3 表格拆行、§5 负对照表改 N2 / 加 N2b、§6 记「已签 2」。
- `audit/SIGNOFF.md` 记 HUMAN 原话与「未逐条复核」的部分。

**残留（如实写）**：`record_d5_evidence` 在 `--posted-on` 不可读时**根本不落产物**（exit 2），所以这条改动
在当前 CLI 路径上只是第二道防线；它真正的价值是**任何直接调 `judgeD5` 的地方**都不再会得到一句假话。

## 2. A · 面板运行的负载记录（`BS-54` 的另一半）

R68 把 25 次首屏读数变成分布（真实运行 median 921ms / p90 2439ms / max 5557ms），并**明确拒绝**归因长尾——
因为产物记了结果、没记条件。A 把条件补上：

- `scripts/lib/load-sample.mjs`：`cpuTimes()`（`os.cpus()` 累计时间的差；**不用 `os.loadavg()`**，Windows 上恒 0，
  R37 已为此付过一次学费）+ `busyPercent()`（纯函数）+ `describeConditions()`（带 `limits`）。
- `record_client_serve` 在整轮开始/结束各采一次，产物新增 `conditions.cpu.observed_busy_percent` 与
  `conditions.window.{started_at,ended_at}`，并写清 `loadavg_usable`。
- 4 条单测：**差值不是绝对值** / 零长窗口与计数器回退一律 `null`（**不许编数字**）/ 计数器单调 / `limits` 在场。

**它不回答什么**：内存/磁盘/网络压力、其它用户、以及「负载在哪一秒达到峰值」——一次多分钟的运行只能给一个数。

### 2.1 顺手抓到的真缺陷：`--dsh-main` 缺省时指向仓库根

第一次跑 A 时我没给 `--dsh-main`，脚本把空串 `pathFor('')` 解析成**仓库根目录**，而守卫只检查
`existsSync(...)`（目录当然存在），于是执行 `node <仓库根> plugin install` → `Cannot find module '<repo>'`，
产物里记成 **`install: failed`**。

这是 **R50 同一个家族**：配置没给，却看起来像产品坏了（那次是「检查没跑起来却报 token 401」）。
现在守卫要求 `--dsh-main` 必须是**一个文件**，否则 exit 2 并打印期望的路径；红产物已删除（它不是产品证据，是错误调用）。

## 4. 本轮新增的三条坑

1. **缺省值指向「看起来合理的地方」最危险**：`--dsh-main` 缺省被解析成仓库根目录，`existsSync` 通过，
   于是 `node <repo> plugin install` 的报错被记成 `install: failed`——错误调用被读成产品失败（R50 家族第二次）。
2. **负载读数必须写明它不是什么**：`os.loadavg()` 在 Windows 恒 0；产物里现在有 `loadavg_usable: false`，
   免得下一个人再试一次并得到「机器全程空闲」的假读数。
3. **条件记录只对未来的运行有效**：给历史观测补条件是做不到的，所以「长尾可归因」要等下一次慢跑。
