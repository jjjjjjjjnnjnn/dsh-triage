| # | 事实 | 影响 |

## 4. 四轴

### 4.1 正确性

- 没有样本就没有相位，没有相位就不出结论：`judgeProbe` 的输入只有「步骤结果 + 样本行 + 截获的 HTTP」，不含任何直接读 fs 的路径；
- 「0 行 / ≥2 行 / 非 active」是三种不同结论，没有被合并；
- `go` 的文案限定在 boot + HTTP + 行相位，且 `limits[]` 写进产物。

### 4.2 可复现

- 判定是纯函数（17 条单测，无 I/O）；I/O 全部注入；
- 两份红跑用 `--expect` 自检：fixture 哪天「修好了」，脚本 exit 1；
- 同一命令三次真跑 boot→sample 11.8 / 12.3 / 13.8s，均 < 20s。

### 4.3 合规 / 许可

- 只读上游 MIT 产物与其 schema 文本；未 vendor、未复制实现；
- 沙盒 env 经 `scrubbedEnv` 丢弃 `*_API_KEY` / `*TOKEN*` / `*SECRET*` 等，不读 `~/.dsh/credentials`；
- 产物经 `makeRedactor` 脱敏（含 `file:///` 百分号编码变体）。

### 4.4 SSOT

- 三份 probe 产物 + 一份 inventory-live 产物，全部 `produced_by` + `generated_at` + 纯 hash `.sha256`；
- `data/results` 无孤儿（`step-review` 的 `no-orphan-results` 通过）；
- 历史台账中 hooks 路径随迁移更新（R12-S1 / R12-S6 / R13-S2），**审核结论未改**，文本里注明迁移。

## 5. 对抗性（自己构造 + 真机反例）

| # | 攻击 / 反例 | 结果 |
|---|---|---|
| F1 | 「进程还活着」当成功 | 判据是样本文件，不是 `exitCode`；boot 超时 → `probe.boot-timeout` |
| F2 | HTTP 200 当「UI 好了」 | `client-rendered` 恒 `unmeasured`，单测断言 |
| F3 | 候选行 0 条当「没问题」 | `probe.row-missing` → blocked |
| F4 | `failed` 与 `null` 合并成「没起来」 | 两条理由同 id，但 `params.phase` 区分（`failed` / `none`），两份产物对照 |
| F5 | 清理失败但结论照旧 | `probe.cleanup-incomplete` → `risky`，测量结论保留 |
| F6 | dry-run 顺手起进程 | e2e 断言沙盒根目录条目数不变 |
| F7 | 候选包名靠猜 | 解析失败 → exit 2，不跑 |
| F8 | 我们自己的 patch 形态错误 | 真机抓到并修，门新增 `rows-are-inserted`；手工反向注入 → 红并点名 `compat-verdict` |
| F9 | 沙盒 env 带真实凭据 | `scrubbedEnv` 单元可查；产物 `sandbox.env_scrubbed=true` |

**失败的对抗**：`--mutate` 只要求「每门非 0 退出」，一门因无关原因崩溃也会记 CAUGHT——这条边界写在 R14-S6 的 adversary 轴里，未解决。
