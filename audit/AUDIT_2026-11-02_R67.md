## 1. 做了什么

### 1.1 `T-836`：D5 的窗口起点不再接受「不存在的时刻」

`windowOf()` 之前用 `Date.parse`。它把 `2026-02-30T12:00:00Z` **滚成 3 月 2 日**并返回一个有限 epoch——于是窗口整体推后两天，
判定仍然算得出来、而且看起来合法。现在改用 `parseInstant`（R66 的往返校验）：

| 输入 | 修前 | 修后 |
|---|---|---|
| `2026-02-30T12:00:00Z` | 窗口 = 03-02 → 03-16 | **无窗口**（`posted_on: null`） |
| `2026-13-01T00:00:00Z` | `NaN` → 无窗口（碰巧对） | 无窗口 |
| `2026-11-02`（裸日期） | 当 UTC 零点 | 无窗口 |
| `2026-11-02T18:36:00+01:00` | 同 `17:36Z` | 同 `17:36Z`（单测钉死两种拼法 `deepEqual`） |

**残留（如实写）**：无窗口时 `judgeD5` 报 `no-post`，对「日期是垃圾」来说这个词不准确。CLI 入口已经先挡（R66），
这里是第二道防线；把 `no-post` 拆成 `unmeasurable` 属于判定顺序的改动，需要改 spec + 签字，所以**没有在这一轮做**。

### 1.2 `T-835`：记录器的「打印路径」= 「实写路径」

一天内同一个 bug 被抄了两次（`watch_next_release` → `record_usability_smoke`），根因是每个记录器各自拼输出。
现在抽出 `scripts/lib/evidence.mjs#writeEvidence()`：

- 写入 + 同目录 `.sha256`，**路径由同一个变量派生出打印值**（在仓内打印相对路径，在仓外打印绝对路径，两种情况不会长得一样）；
- 已存在则拒绝覆盖（返回值 `{ok:false, reason:'exists'}`，调用方 exit 2）；
- `record_d5_evidence.mjs` 改用它；`%TEMP%` 对照实测：打印出来的是 `C:/Users/…/r67-d5-out/d5-selftest-…json`，与落盘一致（修前会打印 `data/results/…`）。

**并且把这个 bug 类做成机器检查**（`tests/governance/evidence-and-dates.test.ts`）：任何**接收 `--out`** 的脚本，
源码里不得出现 `ssot data/results/` 这种硬编码打印。当前 45 个收 `--out` 的脚本里，只有 `record_d5_evidence.mjs` 命中，已修；
其余 5 处硬编码的文件（`gate` / `record_audit` / `record_case` / `render_inventory` / `bootstrap_upstream`）**都不收 `--out`**，所以它们的打印是对的——这条断言能区分「对的硬编码」和「错的硬编码」。

### 1.3 顺手修掉一个隐私漏（`results-privacy` 真的红了）

构造 selftest 时把 `--fixtures` 指向 `%TEMP%`，产物里的 `sources.reactions` 写了
`fixtures:C:\Users\<name>\AppData\Local\Temp\…`——**绝对路径进了 `data/results`**，门当场红（红产物已删除、未提交）。
修法：`sources` 只写 **fixture 目录名**（读者需要的是「用的是哪套夹具」，不是它在盘上的位置）。重跑后匹配 `Users|AppData` = **0**。

### 1.4 `T-837`：两份手写日期必须指同一个时刻

`registry.json` 的 `posted_on` 与 D5 产物里的 `window.posted_on` 是同一个事件的两处手写值，之前**没有任何东西比较**。
新增治理测试：取最新一次 `d5-evidence-*` 产物，按 `post.url` 找回 registry 里对应的 `posted` 条目，
要求两者 `parseInstant().epochMs` **相等**（比时刻，不比字符串，所以 `Z` 与 `+01:00` 两种写法都算对）。

## 3. 边界（不许外推）

- 那条 selftest 用的是**夹具**（`reactions.json` 写死 3），所以它不是「D5 现在有 3 个赞」的证据；真实读数仍以最近一次
  `d5-evidence-*` 为准（0/10 · 0/1 · 634 burst）。
- 记录器输出断言只覆盖「收 `--out` 的脚本」；不收 `--out` 的脚本仍然可以硬编码，这是有意的（它们的打印是对的）。
- `writeEvidence` 不做 schema 校验、不决定文件名，也不清理旧产物。
